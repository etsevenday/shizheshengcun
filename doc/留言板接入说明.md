# 留言板接入说明

2026年10月23日 ｜ 适用于网页原型 v0.1 起

朋友在游戏里按 **F**（或点顶栏“反馈”、菜单、标题页、死亡结算里的反馈按钮）即可留言。留言会自动附带：

| 自动附带 | 内容 |
| --- | --- |
| 当前画面 | 打开留言框时自动截图，可删除，也可以再截一次 |
| 系统环境 | 操作系统与版本、浏览器与版本、窗口与屏幕尺寸、缩放、语言、时区、页面地址、构建号 |
| 游戏状态 | 第几日几点、所在地点、当前界面（地图/加工/休息/暂停面板……）、进行中的行动与进度、六项状态、负重、火堆与设施、随身与地面物品、最近12条日志、种子 |
| 存档 | 默认勾选，可取消；用来原样复现问题 |

截图支持 Ctrl+V 粘贴、拖入和选择文件，最多6张，自动压缩到长边1920像素。

## 现在的状态：未连接服务器

`web/Survival.Web/wwwroot/feedback.json` 还是空的。此时朋友点“提交”，留言会被**复制为一段文字**，截图可点“下载截图”，再通过微信发给你。功能可用，只是不会自动汇总。

## 连接 Supabase（约10分钟，只做一次）

1. 打开 https://supabase.com ，用 GitHub 账号登录，新建一个免费项目。区域选离朋友近的，例如 Singapore。
2. 进入项目的 **SQL Editor**，把 `tools/supabase-feedback.sql` 整段粘贴进去执行。它会建好 `feedback` 表、`feedback-screenshots` 存储桶、公开的 `feedback_wall` 留言墙视图和权限规则。
3. 进入 **Project Settings → API Keys**，记下三样东西：
   - Project URL，形如 `https://abcd1234.supabase.co`
   - Publishable key（`sb_publishable_` 开头；旧项目叫 anon key）。**这个是公开的**，会写进网页。
   - Secret key（`sb_secret_` 开头；旧项目叫 service_role key）。**这个只放你自己电脑，绝不提交、不发给任何人。**
4. 把 URL 和 Publishable key 填进 `web/Survival.Web/wwwroot/feedback.json`：

```json
{
  "supabaseUrl": "https://abcd1234.supabase.co",
  "supabaseKey": "sb_publishable_xxxxxxxx",
  "table": "feedback",
  "bucket": "feedback-screenshots"
}
```

5. 在仓库根目录新建 `.feedback.local.json`（已在 .gitignore 里，不会被提交）：

```json
{ "supabaseUrl": "https://abcd1234.supabase.co", "serviceKey": "sb_secret_xxxxxxxx" }
```

6. 提交并推送 `feedback.json`，等 GitHub Actions 发布完成。之后可以用下面的命令检查连接：

```bash
python tools/feedback.py ping
```

> 也可以把第4、5步交给 AI：在对话里说“留言板配置好了”，并把 URL 与 Publishable key 发给它即可。Secret key 请自己填进 `.feedback.local.json`，不要发在对话里。

## 权限设计

- 访客（Publishable key）可以**新增**留言、**上传**截图，并在弹窗的“大家的留言”页看到**所有人**的留言、截图、处理状态和作者备注；不能修改或删除。
- 公开读取只走 `feedback_wall` 视图，它只暴露留言正文、称呼、分类、状态、备注、截图和版本号；存档附件、页面地址、浏览器信息留在 `feedback` 表里，访客读不到。
- 标记处理状态、读取存档附件需要 Secret key，只在你本机的收件工具里使用。`mark` 时写的 `--note` 备注会直接显示给所有访客，相当于公开回复。
- 数据库约束限制了留言长度、截图数量（6张）、单张大小（3MB）和图片格式，防止被塞爆。

## 收留言、让 AI 改

```bash
python tools/feedback.py list
```

```bash
python tools/feedback.py pull
```

`pull` 会把每条未处理留言下载到 `feedback-inbox/<时间>-<编号>/`，里面有 `feedback.md`（正文、环境、游戏状态、最近日志）、截图和 `save.json`。该目录也在 .gitignore 里，玩家的截图与存档不会进入公开仓库。

之后可以直接对 AI 说：

> 拉一下新留言，逐条看 feedback-inbox 里的内容，小问题直接改并跑测试，改完把对应留言标记为 done，备注提交号；需要策划拍板的列出来问我。

处理完成后标记状态（编号写前几位即可）：

```bash
python tools/feedback.py mark 1a2b3c4d done --note "已在 abc1234 修复"
```

状态有四种：`new` 未处理、`doing` 处理中、`done` 已处理、`wontfix` 不处理。留言墙上分别显示为“待处理 / 处理中 / 已处理 / 暂不处理”。等策划拍板的留言可以标成 `doing` 并备注“等策划案”，朋友打开留言墙就能看到。

## 复用到别的网页项目

留言组件是一个独立文件 `web/Survival.Web/wwwroot/js/feedback-widget.js`，不依赖本游戏。在别的项目里：

1. 复制该文件，页面里引入。
2. 调用 `FeedbackWidget.init({ project: '项目名', configUrl: 'feedback.json', floatingButton: true })`。需要附带应用状态时再传 `getContext` 与 `getAttachment`。
3. 同一个 Supabase 项目可以给多个游戏共用，靠 `project` 字段区分；收件工具用 `--project 项目名` 读取。
