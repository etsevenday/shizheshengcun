## B41e1.3 开发假设（只涉代码结构、内部命名与排版）

1. 敌踪卡的选中沿用 `SelectionKind.Enemy`。开关开时 `Selection.Id` 存卡键（`we:`／`group:`／`fixed:`／`elite:`），单卡另在 `InstanceId` 记世界敌人号，其余为空。开关关时仍是旧写法（`Id` 与 `InstanceId` 都是世界敌人号），两种写法由 `CardsV2` 区分，不新增选中种类。
2. 操作盘沿用就近浮窗 `G.Pop`（种类 `"enemycard"`，`Id` 为卡键），由 `AnchorPop` 居中显示。Esc、遮罩、×、「返回」都走已有的「居中局部盘」一层（`NormalEscOwner` 的 `Disk`／`Pop`），所以 `GameSession.Keys.cs` 未加新层。旧 `EncounterEscOwner` 只在旧敌踪覆盖层时用，新版不会出现该覆盖层。
3. 卡的 DOM id 为 `ecard-` 加卡键，冒号换成连字符（`LocationStrip.EnemyCardAnchor`），收盘后焦点回到它。
4. 卡面排版：
   - 常驻单卡、可选强敌的副标沿旧卡写「健康 {当前}/{上限}」，第二行有健康条。
   - 固定战副标沿旧卡写名单，第二行有「已交过手：…」时照旧显示。
   - 第二行最后一行是卡面状态句。
   - 卡上不再放按钮，处理按钮都在盘里。
   - 角标样式：中立用无色，其余沿旧卡的强调色。
5. 悬停句按行返回，卡的 `title` 用换行连接，不另加标点。
6. 操作盘排版：
   - 副标写卡的角标。
   - 信息标签逐行「标签｜值」，与煅烧木炭盘同一种行样式。
   - 「接近」行在还没抽接近时间（状态句为空）时不显示。
   - 「成功率」行写「潜行接近 成功率X%」，可躲避时接「 · 躲避 成功率Y%」；固定关键敌人不写躲避成功率。
   - 每个成员先一行「{敌人名} 健康{当前}/{上限}」，再接原盘的命中／伤害／武器命中一行和原感染句。
   - 弹仓为 0 的提示写一次。
   - 三个按钮各自的禁用原因去重后逐条写在盘内，并作按钮悬停。
7. 详情排版：
   - 眉标写「敌踪详情 · {地点}」，标题写卡名，下方一行写「{角标} · 警惕{等级}级」。
   - 每个成员一组原详情行，成员名放在组首行的标签位。
   - 「开战武器」与感染句只写一次。
   - 不能主动接近时，原因写在正文。
   - 页脚只写敌人详情脚注。
8. 提交时带上本次渲染算出的队长与成功率（闭包捕获），内核比对不一致时返回原句「当前情况已变化，请重新选择后再操作。」，显示在盘内。

## B41e1.4 实施记录与偏差

1. **敌踪卡（Q427、Q446 ⑥）**：
   - 开关开时，一个「敌踪」分组按 `EnemyCardsHere` 顺序（固定战、可选强敌、组卡、单卡）排列。
   - 标题、角标与危险叠层直接取卡视图：组卡「{首名}等{N}只」＋「敌踪待处理」＋危险；固定战原标题＋「守卫／固定」；可选强敌＋「可选强敌」；单卡「敌对／中立」，精英挂危险。
   - 第二行状态句按内核顺序取一条：可选挑战、首战门控、中立、保护、到期、倒计时。
   - 悬停：常驻、固定战、可选强敌第一行为脚注句，最后一行为状态句；固定战在中间另补「必须战胜这处敌踪，才能解除对应的资源或路线限制。」。
   - 安全屋屋内不出卡（内核本就返回空）。
2. **居中操作盘**：
   - 点卡即选中并打开盘。
   - 「主动接近」点击即提交（0 分钟），开战后按原入战流程收盘、清选中、进战斗循环。
   - 「潜行接近」「躲避」点击即提交 5 分钟行动，开工后收盘，判定入战时接战斗。
   - 不加第二次确认，不贴 Enter；「返回」带 Esc 键帽。
   - 固定关键敌人（含教学卡）的躲避按钮禁用，盘内写「这是必须战胜的敌踪，无法躲避。」，触屏与键盘都能读到（B41-TEXT02 的这一项）。
3. **Q447 预览**：
   - 组卡、固定战按锁定名单原顺序逐个成员列命中、伤害、武器命中、感染。组卡不列隐藏中的成员，与内核主动接近实际入场一致。
   - 可选强敌首次处理前没有实例，按挑战敌种的满血数值预览，不创建敌人。
   - 受惊预览：主动接近／潜行接近一行，按 0.5 情境；可躲避时另一行以「躲避失败时」开头，按 1.0 情境。
   - （偏差，次要）受惊预览没有逐成员写，而是整卡一行。原因：现有 `FearNote` 按全名单取真实受惊源，实际入战也只按这一名判一次；逐成员写受惊率会让人以为每只都判一次。命中、伤害、感染是逐成员写的。
4. **Q457 收盘重验**：盘每次渲染都用 `EnemyCardHere` 重验（卡失效、隐藏、交战、离开当前地点或区域都算失效）。失效即收盘，同时清掉该卡的右栏详情、回默认内容，不改选别的敌人。选中与悬停在开关开时也按卡键重验。
5. **敌踪详情（Q446 ④）**：
   - 去掉旧「不受随机接敌保护期限制」，保留真实受惊预览。
   - 参战范围：单卡、可选强敌写「只与这一只交战」；固定战沿旧卡悬停原句「全名单一起入场（从1号位起）」；组卡不写。
   - 固定关键敌人（`KeyEnemy`：教学卡、固定战、守卫、检查哨，R05 Q420）补关键敌人句；页脚写脚注句。
   - 旧页脚的「ESC 不能关掉战斗」后缀在新版页脚没有保留（新页脚只写脚注原句）。
6. **读法说明（次要）**：
   - 卡悬停的「必须战胜说明」按 Q446 ⑥ 字面只加在固定战卡（`fixed`）上；教学单卡属常驻卡，不加。
   - 详情的「固定关键敌人详情补句」按 `KeyEnemy` 加，所以教学卡在详情里有这一句。
7. **卡面去掉的旧信息**：
   - 可选强敌卡在开关开时不再写旧 `EliteNote`（特殊掉落说明），原因是其中「首次接战时抽定」属 Q446 ⑤，归 B41e2 一起改。
   - 固定战卡不再写旧「{N}只 · 名单已锁定 · 不增援」，第二行改为状态句。
8. **测试**：
   - `dotnet build web/Survival.sln`：0 错误。
   - 开关关：`dotnet test web/Survival.sln` 2344 项全部通过（批前 2331 项，本批新增 13 项）。
   - 开关开（`SURVIVAL_ENEMY_CARDS_V2=1`）：2342 项中 121 项失败。在开工前提交 9ff2726 上同样跑开关开，也是 121 项失败，两份失败清单逐项相同。本批新增用例全部通过。失败的都是 B41a—B41c 记录的旧流程断言，留给 B41e3。
9. 本批没有启动浏览器预览，界面走查留给试玩：开关开要在本地配置或测试环境里打开。
