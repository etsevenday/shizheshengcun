## B50a.3 开发假设

以下为代码结构、命名、排版等开发方自定，不涉及规则、数值或新玩家文字：

1. 来源账存在腐败物实例上（原物 ID → 已知份数），合堆／批次键不变；拆堆一律走同一 `SplitOff`，按原物 ID 升序先分已知份、再分未知份。
2. 停止原因在停止那一刻写进晾制位；展示时缺料、未知各走自己的文字，腐败与旧档标记走现行腐败文字。
3. 操作窗批次条里腐败物只写物理明细一行（不再单独加粗份数，因明细已含「×{总份数}」）；后层悬停按「第{序号}批×{数量} · 每份…公斤（· 每堆最多…份） · 预留 · 来源：…」用「 · 」连接。
4. 物品详情的「来源」行放在合计／单件重量之后；只有一批的腐败物不另起批次行，重量仍由原合计／单件重量行给出。
5. 重置窗两句腐败统计放在遗留物清单之后、沿原警示样式；晾制架摘要各段顺序为晾制中、待取、缺料、停止、腐败、空。
