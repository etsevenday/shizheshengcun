## B37a1.3 开发假设

只涉代码结构、命名和排版：

1. 素材按内容去重：同一张图在 a9b93f0 里有多个文件名（如各地牢分层底图）只拷一份，运行时清单的 `files.<名>.sources` 记全部原名，绑定按原名对照。文件不重编码、不缩放、不改名（取第一个原名）。
2. 运行时清单作为嵌入资源 `ink-v2.json` 进程序集，启动不另发网络请求；图集按实际显示的 `<image>` 由浏览器按需载入。
3. 精灵用内嵌 SVG 裁窗（外层 viewBox = 清单 crop，内层 image = 图集原尺寸），不切小图。
4. 界面已有的旧键（物品 ID、`enemy_*`、`status_*`、`cmd_*`、`fists` 等）保留调用处不动，由 `ArtCatalog.Resolve` 统一映射到稳定 ID；新接的图位直接写稳定 ID。
5. `ArtCatalog` 是不依赖 Blazor 的纯类，测试项目用 `Compile Include … Link` 直接编译它（WASM 项目不能被测试项目引用）。
6. 清单里取不到的键统一画占位并记入 `Icons.Missing`；状态类的缺图落到清单里的 `status:status_unknown`。
7. 地牢房间场景按清单原绑定（同一地牢的分层底图共用一个文件）；Q837 的 37 处按地点 ID 前缀判定。
8. 最近邻只写在根上一处，靠继承覆盖 `<img>`、SVG `<image>` 与 CSS 背景图。
