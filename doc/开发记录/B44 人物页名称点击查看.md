## B44.3 开发假设（只涉代码结构、内部命名与排版）

1. **名称控件只包实际名称。** 装备槽行只把物品名做成按钮（槽名、图标、重量、耐久行、维修说明都不是）；队员行只把姓名做成按钮（号位、类别、速度、数值行、身份、武器行都不是）。按钮外观沿原名称文字：装备名保留品质色，姓名保留粗体，去掉按钮底色与边框，指着时加下划线（提示可点，没有新增文字）。
2. **行高亮。** 指针在行上或行内任一控件有焦点（`:hover`、`:focus-within`）时整行加浅色底；空槽行不高亮（没有对象）。行本身不再可 Tab 聚焦（BM1 为悬停入口加的 `tabindex="0"` 去掉），Tab／Shift+Tab 直接在名称与各按钮之间移动——S14 写的是「聚焦行、名称或按钮只给焦点」，行不可聚焦不违背，且少一个无作用的停靠点。
3. **ENTER 键帽。** 放在名称按钮里、名称之后（同 B43「键帽是按钮的一部分」），`aria-hidden`（读屏读按钮的可访问名「查看…详情」）；只在名称有焦点（`:focus`）时显示，未聚焦时不占行宽；文字按逐字稿写大写「ENTER」（`PeekNameView.Cap`），与 B43 局部确认键帽「Enter」（`ShellKeys.Enter`）写法不同，照策划原文未统一。聚焦时名称描框（向外 1px，不压字）。
4. **详情沿用悬停覆盖状态。** 点名称后的详情与原 Q483 是同一个右栏覆盖（`HoverPeekState`，键 `worn|实例`、`member|成员`），因此生命周期与原来一致：移开不回、点页签结束、换面板／地点／读档清、对象失效清；之后悬停右栏外的真实对象会按全局 HOVER 规则替换它。名称激活与悬停同一受理条件（对白锁、菜单、死亡、放下数量框开着、全屏战斗、对象失效时不受理）。
5. **焦点交接。** 进入：右栏绘制后把焦点交给详情标题（`[data-peek-shown] h2`，脚本补 `tabindex="-1"`；鼠标进入时不画焦点框，键盘进入时有）。返回：只在读者点「人物」页签、且右栏此刻显示的仍是由名称打开的那一项时，焦点回到该名称（同一对象键的按钮）；原名称已不在（卸下、离队等）时回「人物」页签。点「对象」页签、被右栏外悬停替换后再点「人物」、回收箱卡「取出…」跳到人物页、读档／新局都不拉焦点。
6. **回车不穿透。** B43 试玩修复把「二级面板开着时停在面板外控件上的焦点」当作没有焦点、回车归面板唯一确认。右栏不被二级面板盖住，所以键盘聚焦（`:focus-visible`）在右栏控件上、或焦点在名称按钮上时，回车按该控件原生语义，不再触发面板的确认。鼠标点过的右栏按钮仍按 B43 原规则（回车归面板），不扩大改动。
7. **点击不冒泡。** 名称按钮 `@onclick:stopPropagation`；名称与行内按钮是并列的兄弟元素，互不包含。
8. **Q493 范围。** 只在 `FacilityCard` 的未建设施悬停（遮蔽棚、床垫、无工坊时的工坊卡）传 `UnbuiltPeek`；制作面板里悬停其他配方、点击进制作后的右栏仍是原脚注。悬停版脚注只换最后一行，详细预估其余内容不变。

## B44.4 实施记录与偏差

1. 人物页：装备展开后每个已穿戴槽、队伍块里每个队员（含「你」、候补）——指着行只出现浅色底，人物页不换；点物品名／姓名，右栏换成与原 Q483 同一份只读详情（装备：位置行「穿戴·{槽名}」、名称品质、说明、重量、耐久成色、武器与各装备行；队员：号位或「候补」、姓名、类别、背景句、速度、六项与病毒、候补照护、身份、武器），页签亮「对象」。
2. 键盘：Tab 依次到「物品名 → 卸下 → 维修 → 现场修补 → 放当前地面」、「姓名 → 编入同行／留作候补／留守此屋 → 展开随身物品 → 各食饮按钮」，人物页不换；名称上显示「ENTER」，按 Enter 或空格进入详情、焦点到详情标题；Shift+Tab 回到「人物」页签按 Enter 返回，焦点回原名称，可继续 Tab。
3. 原 BM1 行内按钮区、展开按钮、随身物品列表上的 `data-peek=""`（当时用来挡整行热区）已无作用，一并去掉。
4. Q493：未建遮蔽棚、床垫、工坊卡悬停的右栏底部现为「时间为预计值」，原来是「在中间配方卡下方点“开始建造”；时间为预计值」。
5. Q494：与现状一致，未改代码；新增用例覆盖「互不包含两行都留」「带后缀仍整段包含照样去重」「后缀不同不算相同」。

## B44.5 试玩修复（M755，2026-11-12）

线上试玩（1705438、5289147 推送后）发现两处违反 Q492-A01 的排版问题，一次提交修完，行为未改：

1. **1280×720 装备名称宽度为 0**：右栏人物页装备行的名称按钮被图标（22px）与重量（不收缩，约 63px）挤成 0 宽，鼠标看不到也点不到，聚焦时 ENTER 也看不见。原因是 `fourrows.css` 的 `.equip-row .eq-name { min-width: 0; overflow: hidden; … }` 后加载、盖过 `app.css` 的 `overflow: visible`，且名称可收缩到 0。改为（`cards.css`，只作用于右栏装备行）：`.eq-item` 允许换行；名称按钮 `flex: 1 1 0`、最小宽约 3.5 字，名称文字（新包一层 `.peek-name-text`）单行省略、不再两字一行；放不下时重量整块换到下一行靠右，不被挤没。
2. **1600×900 聚焦时「ENTER」被裁成「ENTE」**：同一条 `overflow: hidden` 裁掉了按钮里的键帽。名称按钮改为 `overflow: visible` 的内部弹性排布：键帽不收缩，与名称同排放不下时折到名称下方，名称文字至少留 2 字后省略。
3. 顺带：槽行、队员行悬停／聚焦高亮由 `#ffffff0f` 加深为 `#ffffff1f`。
4. 测试：B44NameViewTests 两处源码断言随改（名称包 `.peek-name-text`、高亮色值）；全量 2237 项全过。本次未在浏览器实测，三档复验交试玩。

## 遗留

没有需要策划补规则、数值或原句才能做的缺口。试玩时要重点看的地方：

1. **三档窗口（1280×720、1600×900、1920×1080）鼠标路线**（Q492-A01）：展开装备，从槽行左侧／上方／下方／右侧移向卸下、维修、现场修补、放当前地面，人物页不换、按钮点得到；队伍块里从各方向移向编入同行／留作候补（在安全屋屋内为留守此屋）、展开随身物品与其中的食饮按钮。点物品名、姓名进入详情；点「人物」回来。空槽没有可点的名称。
2. **键盘路线**（Q492-A02）：Tab／Shift+Tab 逐个经过名称与按钮，名称聚焦时出现「ENTER」与焦点框、页面不换；Enter／空格进入详情，焦点在详情标题；Shift+Tab 到「人物」页签回车，焦点回原名称，继续 Tab 不再自动进详情。原名称已不在人物页（如该件装备在详情显示期间经整备交给了同行者）时，返回后焦点落在「人物」页签。
3. **二级面板开着时**：打开休息或制作面板，右栏切到「人物」，Tab 到名称按 Enter，应只进入详情、不开始休息／制作。
4. **名称按钮排版**：1280 下长物品名换行、品质色、聚焦框与「ENTER」键帽是否挤压右侧重量；队员行姓名旁的类别、速度是否仍在同一行。
5. **触屏**：点名称进入详情，点行内按钮不进详情。
6. **Q493**：主桌面不打开制作，悬停未建遮蔽棚／床垫／工坊卡，底部只有「时间为预计值」；点击卡进制作面板后右栏底部仍是完整原脚注。
7. **右栏外悬停、Q485 内嵌卡**：回归不变。
