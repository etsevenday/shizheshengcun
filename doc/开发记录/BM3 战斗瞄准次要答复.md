## BM3.3 开发假设（只涉代码结构、内部命名与排版）

1. 「当下真实的焦点／鼠标」由页面读：焦点取 `document.activeElement` 所在的敌方锚点（`#foe-{本场序号}`）；鼠标取最近一次真实指针事件（pointermove／pointerdown，触屏除外）坐标处的 `document.elementFromPoint` 最上层元素所在的敌方锚点。被菜单、对白、遮罩盖住时最上层不是锚点，自然取不到；指针移出窗口（`mouseout` 无 relatedTarget）后清空；`inert` 里的锚点不算。合法与否由会话按当前指令目标范围核验。
2. 「一次新瞄准」沿 BM2 的瞄准上下文（所选指令序号、场次、轮次、游标、行动者、所选物品）：同一上下文只初始化一次（`_aimInitCtx`），换指令、切页、换行动者等产生新上下文才再做。读数发生在全屏战斗渲染完之后（`OnAfterRenderAsync`），覆盖数字键、点技能卡等所有进入瞄准的入口；读数回来时上下文已变，或这段时间里已有真实鼠标进入／方向键／聚焦指定了目标，就不用这次读数。
3. 群体指令（霰弹专长射击）按真实受影响集合，不做单个目标初始化（沿 BM2 假设 8）。
4. 敌方锚点的 `focus` 事件（Tab、鼠标按下聚焦）在瞄准中即明确指定该敌人；不合法的也记下以显示其原因并禁用，与鼠标进入同样处理。
5. 瞄准中焦点在敌方锚点上时，**Enter 与空格**都走同一瞄准确认（`BattleAimSubmit`）。空格是该锚点（role=button）的另一种原生激活键，若仍按原生激活会攻击焦点所在那只、与预测不一致，故一并收拢；未瞄准时两键仍只选中查看。按住的重复按键不受理。
6. 确认按钮的指令短名表从 `BattleScreen.razor` 搬到 `GameSession.BattleShortName`（内容不变），以便按钮与右栏指引从同一个 `BattleConsoleConfirmText()` 取字；右栏指引只在该按钮真实存在时显示（轮到玩家、非对白锁、已选非敌方瞄准的指令）。
7. Q513 把未暴击伤害、命中能力构成、暴击伤害、目标健康放进同一个 `.lines` 块，构成为空时少一行、不留空块。

## BM3.4 实施记录与偏差

1. **Q509**：H →「入门与操作」→「键盘快捷键」战斗区第四行显示「执行（当前指令） Enter」，说明不变，全表不再出现花括号。游戏里的瞄准确认按钮仍是「执行拳击 Enter」等真实名。
2. **Q510／Q511**：
   - 鼠标先停在敌人上再按 1：不用再动鼠标，预测、生命条「预计」条纹、锚点高亮和「执行拳击 Enter」直接就绪。
   - 上一轮点敌人攻击后焦点留在该敌人锚点：下一轮按数字键进入瞄准，该敌人（合法时）直接成为明确目标，按钮可用，Enter 打的就是它。
   - 焦点敌人不合法、鼠标下敌人合法：取鼠标下的敌人；焦点不移走。
   - 都没有：保持「请先指定目标。」，不默认第一个敌人（只剩一个敌人也一样）。
   - 瞄准后把焦点移到不合法敌人：按钮禁用并写真实原因（如「射程不足：…」），此时 Enter 不提交、不借旧合法目标；之后鼠标重新进入合法敌人，目标改为它，此时焦点仍在原锚点，按 Enter 打的是鼠标指定的那只，只执行一次。
   - **偏差**：读数在渲染之后进行，进入瞄准的第一帧可能短暂显示「请先指定目标。」，一次往返后刷新为目标预测（本地约几十毫秒，线上视网络延迟）。
3. **Q512**：结束行动：按钮「确认结束行动 · 剩余3AP清零 Enter」，右栏「在操作台点“确认结束行动 · 剩余3AP清零”才提交；ESC 取消。」；防御：按钮「确认 · 防御 · 1AP Enter」，右栏「在操作台点“确认 · 防御 · 1AP”才提交；ESC 取消。」。比原句多了句末「。」（逐字稿模板带句号）。友方／整队选人的底部指引不变。
4. **Q513**：右栏预测顺序为 目标、实际命中率、命中能力 / 对方闪避、暴击（命中后）、伤害（未暴击）、命中能力构成、伤害（暴击×1.5）、目标健康，之后的说明、弹药、耐久、噪声等不变。
5. **Q520、Q522**：核对与答复一致，代码未改。
6. 测试：`dotnet build web/Survival.sln` 0 错误；`dotnet test web/Survival.sln` 2315 项，失败 1 项 `BM2KeyAnswerTests.Q501_A01_EscHelpVerbatim`（DesignSync，S14／逐字稿「ESC 与界面层级」第三段已由 Q506 改写，属 B41c2，本批不修）。本批新增 11 项（BM3AimAnswerTests 10、Q520 用例 1）全绿；BM2 的 Q495 DesignSync 用例照常通过（逐字稿键表行已由策划改为「执行（当前指令） Enter」）。
7. 本地自测：`node tools/playtest/cdp.mjs` 无头 Chrome 1280×720，`?dev=1` 新游戏进首战（1 只游荡尸）与开发入口放游荡尸＋爬行尸后接敌（2 只），走过上面第 2—4 条；控制台无错误。Q511-A01「两只都合法、焦点优先于鼠标」没有实机走到（徒手拳击只能打 1 号位），按源码与用例核对。

## BM3.6 线上复验结论

2026-11-12 线上（构建 8a94fd3）无头 Chrome 三档分辨率复验，控制台无报错：

- Q509：键表战斗第四行「执行（当前指令） Enter」，说明不变；实际按钮「执行拳击 Enter」。通过。
- Q510：鼠标停在敌人上按 1 直接出预测、按钮可用、AP 不变；鼠标不在敌人上且无焦点时「请先指定目标。」、不默认首敌、Enter 不提交。通过。进入瞄准首帧「请先指定目标。」约 35 毫秒后换成预测（读数在渲染后，已知）。
- Q511：两只合法时焦点优先；鼠标再进入改目标，Enter 打鼠标目标且只一次；焦点在不合法敌人时按钮禁用写真实原因，Enter／空格不提交；方向键、真实 Tab 同步目标；连点加 Enter 只结算一次。通过。
- Q512：结束行动 3AP／1AP、防御、调息的指引与按钮业务文字逐字一致，不含 Enter，切换不残留。通过。
- Q513：伤害（未暴击）在命中能力构成之前，其他行完整；三档都能滚到底。首战提示开时 1280×720、1600×900 伤害行仍不在首屏（写成次要 Q528）。通过。
- 回归：点敌攻击、ESC／右键取消瞄准、胜利回地块正常。

试玩中记下的体验问题写成次要 Q528—Q530（首战提示开时伤害行仍要滚动、点「结束行动」后 Enter 不确认、无目标时消耗写法）。
