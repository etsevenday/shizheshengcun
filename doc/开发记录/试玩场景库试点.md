# 试玩场景库试点

2026-11-18。目的：现在的自动试玩是试玩代理用 `tools/playtest/cdp.mjs` 一条命令一步、靠读文字和截图驱动无头 Chrome，一批完整试玩常要 30—60 分钟、耗 token 多，复验也要代理重新一步步点。本试点把试玩路线固化成**可重放场景**，复验与回归改成跑脚本。**只做了工具和试点场景，没有改 git-watch／design-dev／feedback 技能流程**，接不接、怎么接等用户看效果再定（见本文末节建议）。

## 1 做了什么

| 文件 | 内容 |
| --- | --- |
| `tools/playtest/run.mjs` | 场景执行器：零依赖（Node 自带 WebSocket＋CDP，本机 Chrome），一个进程跑完一组场景；每个「场景 × 分辨率」一个独立浏览器上下文，默认 3 个并行；每步后自动检查；截图与基线逐像素对比 |
| `tools/playtest/png.mjs` | 零依赖 PNG 读写与差异图 |
| `tools/playtest/README.md` | 用法、场景写法、选择器、步骤表、fixture、基线维护 |
| `tools/playtest/scenarios/*.json` | 5 个场景（4 个对应试点批次＋1 个面板冒烟） |
| `tools/playtest/scenarios/_lib/*.json` | 4 个步骤片段：`new-game`、`continue`、`dlg`、`save-to-title` |
| `tools/playtest/fixtures/*.json` | 6 份存档局面（共约 880KB） |
| `tools/playtest/fixtures/build/*.json` | 造这 6 份存档的场景（按编号串行，后面的以前面的为起点） |
| `web/Survival.Web/Components/*.razor` 9 个文件 | 只加 `data-pt="…"` 属性，不改行为与样式（清单见第 6 节） |
| `.gitignore` | `tools/playtest/out/`（截图基线、每次结果、差异图都在这里，不入库） |

`cdp.mjs`、`serve.mjs` 原样保留：代理探索新改动仍用 `cdp.mjs` 一步一步走。

用法（详见 README）：

```bash
dotnet publish web/Survival.Web -c Release -o publish/local
```

```bash
node tools/playtest/serve.mjs start
```

```bash
node tools/playtest/run.mjs
```

结果在 `tools/playtest/out/runs/<时间>/`：`summary.txt`（给人和代理看的摘要）、`results.json`（每步记录）、`shots/`、`diffs/`（超阈值的差异图）、`fail/`（失败那一步的截图）。

## 3 一次全量回归耗时

本机（同时还有别的会话在跑），本地 Release 包，5 个场景 × 3 档 = 15 个任务：

| 并发 | 用时 |
| --- | --- |
| 3（默认） | 72—93 秒（连跑 7 次） |
| 5 | 约 65 秒 |
| 单个任务 | 10—14 秒（批次场景）、23—29 秒（面板冒烟） |
| 重造全部 6 份 fixture | 约 53 秒 |

对照：同样这几条路线，试玩代理一步一条命令走一遍是 30—60 分钟／批。场景跑起来不耗模型 token；代理只需读 `summary.txt` 和失败截图。

截图基线稳定性：同一个包连跑 3 次，0 张截图超阈值（处理过的噪声来源见第 5 节）。

试点里顺带发现、未修（交用户决定要不要记成次要问题）：

1. 编队面板（P）里「（前排）」「（后排）」字号 11.67px，低于 12px 下限，三档都有（字号检查报「警」）。
2. 1280×720 净水台 2 批在办时，第二批的「取出」被下方投料操作区盖住，要在批次区里往下滚才看得到（写场景时从截图看到；关键元素检查默认只看第一个匹配，所以没有报成错）。
3. 开发入口菜单里「B35a1 设施试用组（…）」按钮比菜单宽，右侧文字被裁掉（只有 `?dev=1` 才看得到）。

**能自动发现**：
- 路线走不通（按钮找不到、一直禁用、点了没反应、预期文字／数量没出现）——失败步写明期望与实际，附截图；
- 控制台错误、未捕获异常、资源加载失败、Blazor 错误条；
- 横向溢出、关键按钮在某档分辨率下出视口或被盖住、点击落到别的元素上；
- 字号低于下限、文字被截断无省略号；
- 存档往返后状态不一致（场景里写了读档后的断言时）；
- 画面意外变化（截图差异图，只报「警」，要人或代理看一眼）。

**发现不了**：
- 动画、过渡、手感：截图前冻结动画、模拟「减少动态效果」，节奏、闪烁、拖拽手感、悬停提示一闪而过这类看不到；
- 好不好用、文字读起来对不对、和策划案意图是否一致——场景只断言写进去的东西；没写断言的部分即使变了也只在截图差异里出现；
- 没写进场景的路线与分支（新改动的探索仍要代理或人）；
- 随时间推移的问题（长时间挂机、真实时间自动存档的 5 分钟节奏）；
- 对白内容本身：场景默认把插进来的对白按空格读完（记次数），不检查说了什么。

## 5 实施中的取舍

- **选择器**：首选 `data-pt`，其次项目里现成的 `data-*`／`id`（如 `#fac-kiln`、`#mn-field`、`[data-recipe=build_kiln]`、`[data-station-take]`、`[data-dlg-next]`），文字只用在开发入口按钮（文字不归文案策划）和三处标题页／菜单按钮（「继续游戏」「读取存档」「保存并返回标题」）上——前两处的按钮源码被 `B40bSaveShellTests.Q384_PickerWiring` 按整段字符串断言，加属性测试就红，只好退回文字。同理，地图路线区与城市层**灰着的**「出发」按钮被 `B35cShellTests` 整段断言，没加 `data-pt`，用 `.mr-depart` 类名。
- **对白**：首次行为会随时插进剧情对白，并锁住界面。执行器默认在每个动作步前后把 `[data-dlg-next]` 按空格读完，并等对白遮罩 `.dlg-focus` 淡出（约 140ms，期间仍挡点击）。
- **禁用等待**：点击目标禁用时先等它变可用（对白锁、行动收尾、投料后的防连点锁），超时才判失败，报错带悬停原因。
- **截图噪声**：同一个包两次截图会不同的来源已逐个处理——动画与过渡（冻结）、上一步点击留下的悬停态（截图前鼠标挪到左上角）、键盘焦点框出现时机（截图时藏掉焦点框）、设施投料后的防连点锁（该截图 `settle` 1 秒）。截图里有真实时间的（存档卡）用 `mask`。
- **存档**：自动存档每 5 分钟才写一次，所以读档往返和造 fixture 都先走 `save-to-title`（菜单「保存并返回标题」）。fixture 是 localStorage 快照，去掉了多页签占用标记。存档升版本后旧 fixture 读档时自动迁移，不必每批重造；重造后新局随机数不同，截图基线要 `--update-baseline`。
- **晾架停止位**：任务原想要一份「晾架有停止位」的局面，但晾制中的原料保质暂停，靠等时间造不出停止位（停止只来自缺料或旧档），B53a 当时是手改存档；存档有校验和，本试点不手改，改造了 `drying-rack`（晾制中＋随身腐败物）。要停止位需另加一个开发入口（例如「晾制位改成停止（腐败）」），属代码改动，未做。
- **避免「每批一份、写完即废」**：旧 `tools/verify-ui-v*.cjs` 每批一个 300 行脚本、CDP 帮助函数各抄一份。现在执行器只有一份，场景是几十行 JSON；公用流程进 `_lib`，局面进 fixture；场景坏了从 `summary.txt` 能直接看到哪一步、哪个选择器，改一行即可。

## 7 建议怎样接入 git-watch §4.1

保留代理探索，把「走过的路」沉淀下来，复验与回归只重跑：

1. **开发代理**照旧开发；开发记录的「试玩路线」不再只写成文字，同时写成（或改）`scenarios/<批次>-<主题>.json`，起点优先用现成 fixture，缺局面就加 `fixtures/build/NN-*.json`；需要稳定选择器就在 Razor 上加 `data-pt`。
2. **打包后先跑全量场景**（`run.mjs`，约 1.5 分钟）：已有路线全部回归，失败或「错」级问题直接交开发代理修，不必等试玩代理。
3. **试玩代理只做探索**：只试本批新改动、场景没覆盖的地方（体验、手感、文字、策划案意图），仍用 `cdp.mjs`；完整档／轻量档的区分照旧，但「通用回归路线」「快速回归」改为跑场景。代理发现问题后把复现路线补成场景（先红）。
4. **复验**：开发代理修完 → 重新打包 → 只跑相关场景＋全量回归（几分钟），全绿即复验通过；只有需要人眼判断的（截图差异、体验）才再叫试玩代理看差异图。
5. **推送条件**加一条：全量场景通过（截图差异只算「警」，看过差异图确认是预期的就 `--update-baseline`）。
6. 截图基线放在主工作区 `tools/playtest/out/baseline/`（不入库）；每批推送后用推送的包 `--update-baseline` 一次，下一批就以它为准。

接入前建议先在一两批里并行试用（代理照旧试玩、同时跑场景），对比发现的问题和耗时，再决定是否改技能流程。
