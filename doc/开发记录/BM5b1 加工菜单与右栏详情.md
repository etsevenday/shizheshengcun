## BM5b1.3 开发假设

以下为代码结构、命名、排版与动效层面的自定，不涉及规则、数值或新玩家文字：

1. 「移入锅」按钮放在主层工位食材卡正下方一行（次要按钮样式），灰显时原因用小字跟在按钮后；说明句放在按钮的悬停提示与读屏说明（`title`／`aria-description`）里。
2. 来源草稿的“目标”用字符串键表示（主层、工位、某工位某锅、无来源区的查看层），只在玩家明确换层时比较，自动刷新不比较。
3. Tab 循环的可聚焦判定：未禁用、`tabIndex ≥ 0`、可见、不在 `[inert]`／`[hidden]` 内；循环只处理 Tab 键本身，不改其他键。
4. 焦点分硬、软两种：主动操作成功设硬焦点（本次渲染后一次）；自动内容变化设软焦点，渲染后只在 `document.activeElement` 为 body、空或已脱离文档时才移，最多重试 20 帧。
5. 「生效效果」每条一行、整行宽，排在耐久／成色之后、批次与锅内容之前；两列网格沿原 rail-main（容器 ≥420px 两列）。
6. 交战风险两行放在表头副标题区（来源行之后、接近状态之前）：等级用正文字号加粗，通用提示用辅助字号灰字；不加图标、颜色分档。
7. 风险评估在状态副本上做，副本里不计未读完的对白（对白锁只拦真实操作）；会话按界面版本缓存，每次 Notify 失效。

## BM5b1.4 实施记录与偏差

- Q601「换目标清草稿」与 Q588（主层先选来源、再点空工位直接投放）同时成立的做法：主层选的来源绑定到它之后的第一个明确目标；之后再换目标才清。只按“目标变了就清”会让 Q588 主层投放失效。
- 明确移入锅成功后数量框也回 1（与“清投放草稿”一致）；失败留主层、保留原物与已选来源、显示原因。
- 「移入锅」只对配置 `kind` 为 food 的工位物品出现；锅本身、木材、炭等不出现。
- Q603 木材原因只改主层；进入加工位层后仍是 Q556／Q588 原拒绝句（「拖木材到火堆卡是添加燃料。……」），锅层仍是「木材不能放进锅里」，等 Q637。
- Q604 来源区某一行自己消失（例如地面上的那份被别处拿走）时焦点落点策划案没写，本批不处理（列 Q645）；内容页、整设施失效的修复按 S14 Q604 已做。
- Q608 木盾的「固定特性」行在说明组改成原特性句本身（「盾面：盾类格挡减伤60%，不被动增加护甲」），去掉与首屏摘要矛盾的「（相关技能或多人战斗上线后生效）」；其他武器的该注记原样不动（Q638）。整备比较面板仍是原行（Q609）。
- Q613 敌方“后备／波次”：现行入战只取锁定名单前 C 名，其余留在原地、不随同入场，所以评级也只计前 C 名，与实际入场一致。
- Q613 敌方站得太靠后时按“前移 1 格（前格空则移入、有同伴则交换）后重验”估计；协同前压（让前方同伴先补位）、迎击、等待同伴等 AI 分支不模拟。
- Q613 入场恐慌：沿战外命中预估 `OutOfBattleHit` 的原口径不计（入战基础恐慌 (100−M)/2、惊魂未定加值、受惊都不计），只计已有的身体状态。是否应计入基础恐慌列 Q647。
- Q613 弹仓为 0 的弹匣武器、已损坏武器：现在不能攻击，按 R05“不自动预演装填后冒充现在可攻击”计 0；若此时也不满足应急拳击条件，我方输出 0 → 极高。
- Q613 敌踪整张消失（选中或悬停的卡已不存在）时右栏仍是原句「这个敌人已经离开。」；卡在但没有有效活成员时才写新失效句。两者是否统一列 Q646。
- M865 自测发现多段攻击按第一下区间乘段数会把词条平加算多次，M866 改为第二段起按无平加的同一区间（与真实结算一致）。
