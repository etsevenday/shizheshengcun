## B47b.3 开发假设

以下为代码结构、命名、排版等开发方自定，不涉及规则、数值或新玩家文字：

1. 显示快照是领域状态的只读浅克隆（人物、名册、进度、战斗深拷，物品列表共享），只挂在特写事件上、不进存档；结果帧取 33%（与特写层结果字出现的同一时刻）。
2. 生命姿态的“单膝跪”用现有立绘做 CSS 变暗（亮度 .72、去饱和）加纵向下沉的占位（R09 §7【交开发方定】的受控过渡＋静态占位），起身反向；没有新美术。
3. 支援特写的受益者用金色微光标示；结果字沿原状态名 chip 样式；远处镜头沿用既有特写背景（R09 Q692【交开发方定】）。
4. 世界生命镜头每条一段（1200ms × 动画速度），同段多人按真实发生顺序排；记录上限 200 条防止离线推进无限增长。
5. Q619 锁级说明的显示状态仍在 BattleScreen 组件内，渲染时登记到会话，ESC 通过登记的回调收起。

## B47b.5 试玩修复

线上试玩（构建 4b18ad0）发现 5 条违反策划案的问题，修复提交 M943：

- 读档补播（R03 Q617-A02、Q572）：查下来内核这边没有重播——敌方是逐条推进的，每一步先结算、提交再播这一步的特写；某一步的特写播放中「保存并返回标题」，存下的就是这一步已结算的状态，读档后不重算、不重播这一步，下一次推进是游标上的下一名敌人（新结算，战报只多一条，见新增单测）。回标题、读档、新局原本就清播放队列与显示快照（ResetPlayback）。壳里找到的漏洞是旧循环：战斗推进循环在阅读暂停等待结束后只看“还在战斗”，没验代号，期间读入的若是另一场战斗，旧循环会在新局上推进并播放；播放入口在被调用时才取当前代号，过期循环也能在新局上播；世界推进循环没有代号。改为：`PlayFx` 带调用方代号、过期即返回且不碰显示快照；战斗循环等待后先验代号；世界推进循环开工记代号、每段验，过期时不动新局的推进标记、不接新局的战斗。说明：读档后若存档时敌方还没走完，剩下的敌人照原规则从游标继续行动并播各自的特写，这是读档后新结算的出手，不是补播。
- 播放中点击穿透（Q617-A03、Q633）：特写退到全记录等只读子页之下播放时，子页加 `fx-play`：子页本身仍接住点击（不落到背后的战场、操作台），其中的按钮和正文各行不接点击，正文滚动容器照常滚轮／触控滚动；「返回战斗」「回到最新」在播放中及结束帧上不受理。ESC 照原层级。
- 锁级说明 ESC（Q619-A01）：原因是 app.js 处理 ESC 时先让焦点所在按钮失焦（试玩修复 L6），灰卡失焦就收起了锁级说明，这一下 ESC 再落到阅读区上，于是两层一起没了。改为焦点在灰卡上、它的锁级说明正显示时不先失焦：一下只收锁级说明，焦点留在灰卡上、阅读区保留；再按一次照原层级收阅读区。
- 当前行动者濒死（S14 B34）：当前行动者的待机微动态动画会盖掉立绘的 filter／transform。濒死的当前行动者改为停掉待机微动态，立绘照濒死规则黯淡 0.72＋跪姿，等待下令的高亮框（立绘容器上）照常；系统减少动态效果时同。非当前行动者的濒死者核对过：站位立绘上没有别的动画盖住，原规则生效。
- 系统说明位置行：沿其他主题的“{主题} · {条目}”，条目与所在主题同名时只写一次（「濒死与意志」主题下只有一条同名条目，原来显示成“濒死与意志 · 濒死与意志”）。没有新增文字。
- 不修（按指示保持）：只展开「战斗信息」阅读区时特写全屏不透明盖住正文（Q737 待答复，02 Q737 下已补开发方补充）；「濒死」图标占位（Q754）。
- 测试：新增 `B47bWebTests.Playtest1`—`Playtest5`、`B47bFxTests.Playtest1_SaveDuringEnemyStep_LoadContinuesFromCursor_NoReplay`；`B34bPlaybackWiringTests`、`B47bWebTests` 两处按新写法更新。2714 项全绿。本地浏览器未复验。

## 开发入口试玩路线

开发入口：网址加 `?dev=1`，游戏菜单「开发测试」与战斗菜单的「支援与生命态特写（B47b）」组。

- Q615／Q694：常态「支援技能全开（2人队＋10级＋器具）」→ 从地面装上信号哨、盾、医疗器具等 → 遇敌：逐个用护身、挣脱（先被减速）、坚守、保护、掩护、鼓舞、稳心（先攒恐慌）、协同、总攻令、整队、快速装填、应急护理：自身／友方／全队都是一段支援特写，行动者与受益者有动效，结果字只在实际变化时出现（稳心写真实减少量，协同写“下次行动点+{n}”，挣脱写“解除减速”）；快速装填只在锚点短亮。
