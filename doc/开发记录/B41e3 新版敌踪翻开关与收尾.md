# B41e3 新版敌踪翻开关与收尾

批次 B41e3（2026-11-12—11-13）。需求 R135、R151 的最后一部分：把新版敌踪变成唯一流程。本批删除开关 `encounters.enemyCardsV2`，删除旧接敌拦截与绕行流程，按新规则改写或删除旧用例，并做全量验收与风险复核。本批未推送，线上试玩由试玩代理另做。

## B41e3.1 来源与范围

规则与玩家可见文字只取自以下来源：

- R05「敌人卡、种群刷新与遭遇系统」B41 各节：Q416—Q428、Q436—Q447、Q454—Q457、Q463—Q476、Q488—Q491、Q503—Q508、Q520—Q522、Q531—Q541、Q549—Q551，以及对应验收行。
- S01、S02、S08、S13、S14、S15、R01、R03、R08、A06 的 B41 同批节。
- 《重墨 V2 开工裁定与界面逐字稿》B41 各段，包括 Q446 十处旧句表。
- 《开发方待确认问题》上述各题的答复。

本批没有新增或改写玩家可见句。删除的旧句都属于旧接敌／绕行流程。新版里与之对应的新句，B41e1、B41e2 已经按逐字稿接好（见 B41e2.5 的表）。少数旧句在新版里没有对应场景，列在 B41e3.6 待问策划。

本批范围：

1. 翻开开关：删除配置项、`GameEngine.CardsV2` 与全部开关分支。新局直接使用新版卡模型（`EnemyCardsState.ModelVersion = EnemyCardsModelV2`）。旧档（卡模型标记 0）在读档链尾由 `AdoptEnemyCards` 采纳一次。
2. 删除旧流程：
   - 内核删除 `s.Encounter` 全局阻断（「发现敌踪：请先选择接敌或绕行」，共 15 处）、接敌／绕行入口、绕行结算，以及战后 60 分钟全地点随机接敌保护的写入。
   - 网页壳删除 `BattleOverlay.razor`（敌踪选择层）以及各组件里开关关时的旧分支。
3. 旧用例按新规则改写，或删除测旧流程的用例（清单见 B41e3.4）。
4. 全量验收：构建 0 错误，测试全绿（含 DesignSync）。整理验收对照表，没覆盖到的补用例。
5. 风险复核：
   - 战后同一次推进里开下一场时的网页壳收尾。
   - 敌方开战打断推进。
   - 旧档首次读档采纳新版。
   - 脚本玩家（SurvivalBot）与 COMP20 在新版下能否跑通。
   - Q534。
6. 文档同步：
   - B41a—B41c 各【实现同步】注。
   - 02 中 B41 各题「处理结果」。

不在本批：B45、B34—B37、BM4（Q528—Q530、Q552—Q562）。Q552—Q555 仍未答复，本批没有动。

## B41e3.3 开发假设（只涉代码结构、内部命名与排版）

1. 保留 `EnemyCardsState.ModelVersion`，只用来判断旧档是否已采纳新版。新局直接写 `EnemyCardsModelV2`。
2. 按世界敌人号的旧入口（`CanApproach`／`Approach`、`CanEngageFixed`／`EngageFixed`、`CanEngageElite`／`EngageElite`）保留为按卡键入口的薄包装。原因：大量用例与开发入口还在用。玩家界面已全部走卡键入口。
3. 旧档字段（`Encounter`、`PendingEncounter`、`Bypass`、`EncounterGraceUntil`）保留类型与存档字段，只供读档和采纳使用，新流程不再写入。
4. `GameEngine.DebugStartBattle(s, ids, context)` 作测试与开发入口，直接开一场无卡键的战斗（战报写「遭遇」）。它取代旧用例里 `s.Encounter = …; E.Engage(s)` 的写法。
5. 用例：
   - 只测其他系统、不测敌方接近的旧用例，在测试基类用 `NoEnemyApproach`（设引擎原有的不存档运行开关 `SuppressEnemyApproach`）冻结敌方接近。读档对照的用例在读档后同样设上。
   - 教学首战用例改为“到荒地后主动接近教学卡”（`TestBase.ApproachTutorial`）。
6. 网页壳连场判定用战斗号（`BattleState.BattleId`，单局递增），不用对象引用。

### 脚本玩家与 COMP20（不改游戏规则）

- **SurvivalBot**：健康低于上限一半时在营地休息，不出门。
  - 原因：新版敌踪到期会主动开战、不能绕行，原脚本重伤出门会被一路打死。
  - 结果：七日求生 4 个种子全部活到第 7 日。带战斗的两个用例沿原规则，跑不过时标 Inconclusive。
- **COMP20 路线回归**（4 项）冻结敌方接近，用的是引擎原有的模拟开关 `SuppressEnemyApproach`。
  - 冻结范围：只冻结“到期主动开战”。敌踪卡照常生成，随机组卡照常由脚本主动接近打掉。
  - 原因：路线、固定战备战、食水预算都是按旧版“遇敌可绕行＋保护期”设计的。敌方接近照常时，脚本在途中正常战死（第 9—18 日）。死因是脚本策略不足，不是规则错误。
- **新增 `COMP20_NewGame_LiveEnemyApproach_NoStuck`**：敌方接近照常时跑新局教会线先的整条路线。
  - 断言：序章首战照常胜利；途中确有敌方到期开战打断行动；结局只能是走完或正常战死，不许出现锁死、拒绝循环或异常。
  - 当前结果：打断 7 次，第 17 日在第一条线途中战死，无卡住。
  - 敌方接近照常时，脚本会就地休整（重伤先休整、重伤不去招惹组卡）。

### 偏差

1. **连场收尾**（风险①）：复核发现网页壳原有问题，已修。
   - 问题：一次指令或推进结束上一场后，战后边界在同一次调用里开了下一场（Q416 第 4 条）。此时网页壳不收尾上一场，旧目标、草稿、菜单会带进下一场。`BattleLoop` 还会因上一步是“已结束”而退出循环。下一场如果是敌方先手，就停在“等敌方行动”不动。
   - 修法：见 B41e3.2 的表。用例：B41e3Tests `Risk1_*` 两项。
2. **注释清理**：内核各处“开关关时……”“敌踪待处理”等过时注释改为现状，不改行为。

## B41e3.8 试玩修复（M809）

线上无头试玩报的问题，修在 M809。

### B1【严重】撤退离地后不能走回原地点

- **现象**：在农野荒地采集或睡觉时，敌踪卡到期开战，撤退成功退到临时营地，原工作保留暂停。这时从中央暂停层去走回原地，两条路都走不通：
  - 地点卡「前往 ▸」打开的移动浮窗里，「确认移动」灰掉，也没写原因；
  - 区域地图选农野荒地，只显示「行动进行中，地图只能浏览」。
  - 结果原工作只能退出。
- **依据**：R05 Q464、Q473，逐字稿「原暂停层需允许进入既有地图和合法返程移动入口。地图的「前往」及移动确认沿现有用字、耗时和路线条件，不新增传送按钮。」
- **原因**：内核早已允许这种暂停期间移动（Validate 的 RetreatMoveOpen 例外，移动时暂存原工作、到达后放回仍暂停）。网页壳却仍按 IsBusy（有主行动就算忙）把移动入口锁住。
- **修法**：
  - 内核新增 `GameEngine.PausedTravelOpen(s)`，条件是：主行动处于撤退离地保留的暂停（RetreatMoveOpen），且没有子行动、没有暂存工作、不在战斗中。Validate 的移动例外改为调用它，壳层与内核用同一条判定。
  - 移动浮窗（ActionPops 的 travel／mapnode）：「确认移动」改用 `moveBusy`，暂停层开放移动时不算忙，能不能走仍看移动预览。「终止本次远征…」等其他按钮不变。
  - 区域地图（MapOverlay）：
    - 相邻地点照常显示移动预估；
    - 不再显示「行动进行中，地图只能浏览」；
    - 点节点照常在节点旁打开移动确认。
  - 用字、耗时、路线条件全部沿用现有移动入口。没有新增按钮，也没有新增提示文字。
- **缺口**：无。逐字稿已写明沿用现有「前往」与移动确认。

### 成长页练习盘「返回」按钮排版（开发方定）

- **现象**：1280×720 下，`.primary` 自带 `width: 100%`，和「返回」同排时把「返回」挤成竖排两字。
- **修法**：
  - 「开始练习」改为占余宽：`flex: 1 1 auto; width: auto`；
  - 「返回」按内容宽、不换行：`flex: 0 0 auto; white-space: nowrap`。
  - 只改样式，用字不变。
