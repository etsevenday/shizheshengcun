## 3 开发假设（规则解释，不含数值）

1. **配置文件**：新建 `data/config.v0.6.json` = v0.4 配置 + v0.6/v0.5 替换与新增，不手改策划数值；`enabled` 按用户拍板为 true。公式字符串由代码实现，系数按位置读取并校验形状。
2. **v0.5 与 v0.6 冲突以 v0.6 为准**；B501（开关关闭）按拍板标“不适用”；B512/B513 按 v0.6 无夹紧、无取整语义断言。
3. **状态上限按项配置**：H/E 上限 20，N/W/S/M 100；I、V 单独字段，走同一显示格式与 ActiveConditions。
4. **显示**：统一两位小数（M48 起改为四舍五入，见第 4b 节 D1；正且 <0.01 写“<0.01”，负号“−”）；内核保存原始 double，tick 里不舍入。
5. **世界 tick 拆分**：顺序按 v0.6 §16；行动推进与战斗轮末都调用，每段只结算一次；刷新/巡游以绝对分钟游标判定，离线不补。
6. **随机与防重抽**：所有新随机用存档内 Rng、在事务提交时抽；预览一律在克隆上算、不触发接敌；请求号去重窗口扩到 128（工程常数）。
7. **战斗状态**：`GameState.Battle`、`WorldEnemies`、敌踪状态都随存档且 Clone 深拷贝；战斗与敌踪待选时 IsBusy 为真，内核统一拒绝世界交互、拖拽、即时操作。
8. **战斗覆盖层范围**：替换 v0.7 的地图行 + 设施行（组件替换而非叠加，drag.js 不收集隐藏落点）；地面/随身、左栏、右栏、顶栏可见；顶栏导航与 M/C/R/L 战斗中禁用。
9. **战斗确认规则**：战斗内“点动作 → 右栏预览 → 点执行”；战斗中卡下绷带/抗生素/特效药改发战斗指令（2AP），U728 由此实现。
10. **Esc 在战斗中**：拖拽 Esc 优先 → 关详情/预览 → 打开战斗菜单（只含继续、保存并返回标题，不含脱战）；返回标题后“继续”恢复覆盖层与游标。
11. **敌踪选择**也显示在覆盖层位置；地块可见世界敌人放在设施行“敌踪”分组，点卡右栏给“接近”。
12. **尸变**复用死亡结算界面，文案区分。
13. **免疫/病毒/技能显示**：左栏增免疫、病毒（未感染写“未感染”）；人物页加技能区（等级 + 经验/门槛）。
14. **耐久**：BestTool 按成色；锅损坏保留内容；维护配方在制作面板里选目标工具，无可维护对象时禁用并写原因。
15. **开发测试箱**：金属矛/弩/霰弹枪/步枪及弹药只经 `?dev=1` 开发入口或 Debug API 取得，正常流程不可见。测试箱件数是程序为手测定的（策划只列物品），不属于玩法数值。
16. **旧档迁移**：进行中的主行动保留；旧档探索度已越过新箱揭示点的不补发（显示为已搜空）；迁移失败保留原档并提示；提示文案不写死版本号。
17. **SurvivalBot**：补战斗与敌踪处理；七日通关跑不过不改数值、标 Inconclusive。
18. **图片**：新物品、武器、敌人用内联 SVG 简笔图标，页面占位图 0 个；正式美术列入第 8 节。

开发中新增的规则解释（同样不含数值）：

19. **遮蔽棚休息的精神恢复**仍只在营地遮蔽棚生效（沿用 v0.4 实现），v0.6 未改此条件。
20. **拾荒成色**作用于所有“拾荒箱子”产出的工具与武器（锅具箱、工具箱、武器柜、旧储物柜），制作产物为满耐久。
21. **随机接敌的受惊恐慌**：敌踪“接敌”按受惊遭遇（+10），主动接近不加。
22. **主动接近**只与被点的那一只交战（同地其他敌人不自动加入，除非噪声增援调用）。
23. **嚎叫尸恐慌 +8、野猪蓄力冲撞 ×1.5** 取自 v0.5 正文表格（JSON 未单列字段），作为内核常数 `HowlPanic`、`BoarChargeFactor`，并在用例里对照正文。
24. **巡游检查格点**从第 0 分钟起每 180 分钟（刷新从第 2 日 00:00 起每 120 分钟，策划明文）。
25. **病毒阶段警告**（20/50/80）只写日志与提示、不暂停行动（v0.6 “战斗低值警告不阻断”的同类处理）。
26. **抗生素有效时也给 +4 医疗经验**（与绷带同属“有效治疗”）；特效药清除感染同样给经验。
27. **推挡**命中与否都磨损武器 1（与普通攻击一致）。
28. **工具维护**完成给制造经验（按配方基础分钟计算，与其他配方一致）。
29. **撤退体力**按动作基础值，不受熟练度折减（撤退不属于任何武器技能）。
30. **批量制作**整批完成一次提交，中途取消整批返还，不按件部分完成。
31. **撤退成功**放弃本场已死亡敌人的掉落与尸体（胜利才一次落地）。
32. **战斗中途读档**：战斗日志、队列与游标随存档；读档后从游标继续，不重新抽先手、不重抽已结算的命中。
33. **“完成一次块根烹饪”**（第 2 日目标）与七日检查“完成食物加工”共用同一标记，两条都来自 v0.2（当时只有块根）：只认块根烤制或水煮，烤肉、煮肉不算（M48 L7）。
34. **结果提示条**：v0.7 与 v0.6 都没有规定显示时长。按最保守做法：开始新行动、进入战斗、选中卡片（卡下出现操作条）时收起；否则约 8 秒后自动收起（界面节奏，非玩法数值）；同一内容仍在页脚与行动日志（M48 G5）。
35. **数值显示四舍五入**：两位小数改为四舍五入（先加 1e-6 个百分位的吸附量），不再向零截断；理由与反例见第 4b 节 D1。
36. **药品与饮食的预估口径**：卡下操作条与右栏一律写“使用当下”的即时结算值（药品写这一次的实际效果：冷却中写“本次不回血”、病毒前后）；右栏另起一行写“5分钟后（按等待消耗）”的值（M48 G4）。

## 4 实施记录与偏差

1. M36 提交时按旧尺度写的 17 条玩法断言失败（配置先换、玩法后改），M37 一并改写；之后每个里程碑提交前都跑 `dotnet build web/Survival.sln` 与全量测试。
2. 新增 `Fmt` 后发现 19.9999999 这类浮点会显示成 19.99，改为在 ×100 单位上先吸附 1e-4 再截断。`Fmt.T(1.035)` 仍显示 1.03（二进制表示略小于 1.035），属截断语义的正常结果。（M48 起改为四舍五入，见第 4b 节 D1。）
3. 经验计数最初记在战斗内敌人上，敌人在计数前被打死会丢失；改为 BattleEnemy.XpHits 拷贝并在结算时写回 worldEnemyId。
4. R614 日程预算：v0.6 验证记录里“最低体力 7.40”在本实现的 5 分钟段推进下没有逐位复现（同一日程最低值略有差异），用例改为断言“全日体力不归零、不触发低体力线”的规则含义，具体数值列入待确认。
5. R620 层级比例改为统计用例（大量 DebugSpawnCheck 抽样看 96/3.5/0.5 比例与无强敌池地点不出强敌），避免依赖世界游标的长时推进。
6. 世界游标会干扰接敌类用例，测试基类增加 FreezeWorld/Idle 辅助，把刷新与巡游游标推到远处。
7. Save_RejectsIncompatibleVersion 原来替换 JSON 里所有“4”，升级后会误伤数值；改为只替换 SchemaVersion 字段。
8. 菜单浮层加入开发入口后在 1280×720 超出视口，浮层改为限高纵滚，开发按钮不拉伸。
9. Razor 中 `免疫@if` 被当作邮箱地址、属性里的 `\"` 转义失败，分别改为 `@("免疫")@if` 与常量。
10. 带战斗的通关脚本只用简单策略（遇敌踪健康≥60%接敌、出行时主动接近普通敌人、健康<30%撤退）；它证明“能活到第 8 日”，不代表平衡结论。绕行脚本 7 日内随机敌踪 0 次（风险 ≤2%×密度，第 1 日为 0）。
11. 新局 HUD、旧档迁移、战斗各流程都在浏览器复验；战斗中每条指令执行后立即存档，刷新页面后“继续”回到同一轮同一游标。
12. 处理尸体时体力低于 4 会在第一段后按既有阈值规则暂停（“体力低于4，工作耗时增加”），继续后正常完成，属预期。
