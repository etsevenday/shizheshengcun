# 适者生存：基础UI布局与操作修订案

版本：v0.7。更新日期：2026-10-26。用途：交给程序修改现有基础UI，作为本次五项需求的执行依据。

配套：[v0.4统一卡片UI](<../卡片统一与设施烹饪 v0.4/01 统一卡片与次级菜单UI策划案 v0.4.md>)、[v0.4设施与烹饪](<../卡片统一与设施烹饪 v0.4/02 设施内容物与烤制水煮策划案 v0.4.md>)、[原基础UI](<../UI策划 v0.1/适者生存基础系统UI策划案 v0.1.md>)。

## 1. 生效范围与冲突处理

本案修改布局、内容物展示、点火操作、滚动和自身物品使用入口。未被本案替代的物品、地图、加工、行动占用、体力消耗等玩法，继续采用现有有效规则。本案不代表v0.5/v0.6人物与战斗参考案已确定实装，不因UI版本号较高而自动启用其数值。

| 本次需求 | 采用的新规则 | 被替代的旧规则 |
| --- | --- | --- |
| 地块栏两行排列 | 第一行地图与场景，第二行设施与可交互对象 | v0.4所有类型在同一桌面连续排列、空间不足自由换行 |
| 火堆、锅内容直接展示 | 火堆卡内显示锅，锅卡内显示水和食物；在原位置选取、转移 | 点击火堆再逐层进入火堆内容物、指定锅内容物菜单 |
| 两种点火入口 | 拖入工具直接提交点火；点按钮后选工具直接提交点火 | 拖入工具后再到预览按开始；先选工具再点击第二个点火确认 |
| 所有菜单支持滚轮 | 根据悬停栏位的滚动方向处理滚轮，保留滚动条 | 仅拖动滚动条或部分栏位不支持滚轮 |
| 移除左侧自身UI | 人物信息集中到右栏；可自用物品选中后在卡片下方显示操作 | 左栏自身投放卡、拖到自身卡使用，以及随身卡只能在上方出现操作条 |

“不衍生次级菜单”适用于查看火堆和锅的内容；本次明确要求的**点火工具选择菜单仍保留**。数量、目标选择使用卡边操作条，不再打开一层内容物浏览页。这两类菜单用途不同，不构成冲突。

以下补充属于本案为开发确定的UI裁定：资源卡排在第二行设施之后；移除左侧自身投放手势，统一以卡下按钮使用物品；点火5分钟保留，减少的是确认步骤。若以后更改这些裁定，应同步修改本案，避免程序自行补出另一套流程。

## 2. 主界面结构

```text
顶部：游戏标题 / 日期地点 / 区域地图 / 手工制作 / 休息等
┌──────────┬─────────────────────────────────────┬──────────────┐
│左侧状态栏│地块栏·第一行：地图与场景               │右侧信息栏    │
│时间      │[当前地图大画面+探索/清理] [相邻地图] → │[对象][人物]  │
│健康等状态├─────────────────────────────────────┤对象详情      │
│负重      │地块栏·第二行：设施与可交互对象         │或人物信息    │
│目标/提示 │[火堆：锅及锅内水/食材] [棚] [资源] → │行动预测/进度 │
│          ├─────────────────────────────────────┤              │
│无自身卡  │当前地面：[物品图卡] [选中卡下操作条] → │              │
│          ├─────────────────────────────────────┤              │
│          │随身物品：[物品图卡] [选中卡下操作条] → │              │
└──────────┴─────────────────────────────────────┴──────────────┘
```

### 2.1 第一行：地图与场景

第一行只展示当前地图卡和已发现的相邻地图卡。当前地图卡固定在该行最左侧可见位置，相邻地图卡在右侧独立横向滚动；浏览相邻地图时，不把当前地点及探索/清理按钮滚出视野。未知地点依原发现规则处理，不能为填满卡位提前显示。

当前地图卡使用横向大图卡，承载当前地块的主要背景画面。建议占第一行可用宽度的55%—65%，在1280及以上桌面宽度下至少给出清楚可辨的场景；相邻卡沿用普通地点图卡。上述比例是布局起点，不能为凑比例挤压按钮和正文。

第一行建议高180—240px，至少约三分之二面积可看到场景插画。地名、天气、昼夜、探索进度和按钮放在图片边缘的局部衬底上；不再整张覆盖高不透明度暗层。相邻地图同样展示图片、名称、访问状态和移动耗时。图片统一卡框风格，允许当前地图采用更大的横向比例。

当前地图卡直接保留探索和清理按钮。探索满100%移除探索按钮，保留“已充分探索”；清理次数为0时保留禁用按钮及恢复提示。相邻卡只有移动入口；点击移动沿用原确认流程。移除“地块行动”按钮的决定继续有效。

### 2.2 第二行：设施与可交互对象

火堆、遮蔽棚、床垫等设施排在第二行；锅位于火堆时只嵌在火堆卡内，不独立复制到第二行、地面或随身栏。尚未放入设施的锅仍在真实所属的地面或随身栏。

已发现采集资源卡排在第二行设施之后，以间隔和分组标题区分“设施”“采集资源”，不新增第三条地块卡片行，也不把已发现资源入口取消。固定设施和资源点的不可搬动规则保持。

第二行横向滚动，卡片顶端对齐；设施卡可占普通卡的两至三倍宽，以容纳内嵌锅。建议起始高度220—300px，按照实际内容调节，不用压缩图标和文字换取高度。窄视口下允许中部整体纵向滚动；保持两行分组，不把第一行地图混排进第二行。

卡片内的图片区、内容区和操作区应留足空间。正文不小于16px，辅助文字不小于14px，操作热区不小于40px；需要更多空间时滚动，不能用微小锅图标表示全部内容。左侧、右侧保持独立，不随中部纵向滚动消失。

## 3. 火堆与锅的内嵌内容

### 3.1 不再使用内容物层级菜单

点击火堆主图只选中火堆并刷新右栏，不覆盖地块栏、不进入“火堆详情页”。点击锅主图只选中这口锅；点击锅内某个内容物图标，只选中该内容物。每个点击必须阻止冒泡，不能同时选中父火堆或提交其他操作。

火堆卡直接显示：火堆图、燃烧状态、燃料分钟/上限、两个加工位、底部点燃/熄火等原有合法操作。加工位分别显示真实卡片或空位；已完成食品仍占原加工位并保持可见。

```text
火堆 [火堆插画]       燃烧中 / 燃料60分钟
┌加工位A：金属锅#7──────────────────┐ ┌加工位B──────┐
│[锅图] 金属锅       水量100%        │ │[块根图]     │
│[净水图] 净水×2  1000/1000ml [▾]  │ │烤制10/30分  │
│[根图] 生块根#21  水煮10/30分 [▾] │ │[转移▾]     │
│[根图] 生块根#22  水煮10/30分 [▾] │ └─────────────┘
│[转移整锅▾]                        │
└──────────────────────────────────┘
[投入木材 图标]             [点燃]
```

示例中1000ml净水已供两份食材预留，水行需标出“已预留1000ml”，暂不可饮用/转移。实际数量、进度及原因全部由玩法层提供。只展示有真实实体的子卡，空食材位显示空位提示。

锅卡在地面、随身或设施内均采用同一内容结构：锅图与实例名、水量条、液体图标与数量、最多两个食材图标与状态。水量0%也可直接辨认，不能只靠点开详情得知。锅水每份500ml与锅容量1000ml等现有规则不变。

### 3.2 点击选择与三角转移

| 点击位置 | 选中对象 | 卡下操作 |
| --- | --- | --- |
| 锅主图/锅标题 | 整口锅 | 放到当前地面、拾取到随身；在地面/随身时可选择合法火堆锅位 |
| 水图标/水条对应行 | 该锅内指定液体批次 | 转移1份到地面或随身；允许时显示饮用1份 |
| 食物图标/对应行 | 指定食物实例或批次 | 转移到地面/随身；可食用时显示食用1份 |
| 子对象旁三角箭头 | 箭头所属对象 | 直接打开该对象的转移操作条，含数量与目标 |

选中锅内对象后，操作条紧接在该对象展示单元下方，仍在锅卡/火堆卡内。一个时刻仅展开一个选中对象的操作条；不能锅外层和内部食材同时出现两个执行条。改变高度只影响第二行布局，不覆盖另一张卡；必要时滚动到可见位置，不能跳进新页面。

操作条展示对象图标、名称、完整来源、数量、目标和明确执行按钮，例如“取出净水1份到随身”。选择图标、箭头、数量和目标本身不转移，点击执行按钮才提交；只有一个目标时也保留明确执行按钮。固定设施本身没有“拾取火堆”。

三角箭头是转移入口，不再兼任内容物展开/收起开关。内容物保持直接可见；选中与取消选择只改变高亮及操作条，不改变所有权或加工。

### 3.3 拖拽与受限操作

锅主图/标题作为拖动整锅的把手，液体和食材图标作为对应子物品把手。拖整锅时全部内容随行；拖单个食物时不带走锅或另一份食物。按钮、箭头、滚动条和水量进度显示区域不作为整锅起拖把手，避免点击变成搬锅。

直接向内嵌锅投放：水拖入锅的装水热区，生块根拖入锅食材热区；锅卡边界高亮并显示“加入金属锅#7”。食材拖到火堆直烤位则显示“放入直烤位”。目标优先级为明确锅内热区→锅卡→火堆明确热区→普通区域；锅满或混水失败不得冒泡到火堆，变成另一种烹饪。

保留现有转移默认1份、Shift数量选择、整次超重拒绝和唯一owner规则。火堆内整锅和锅水/食物必须带真实实例路径，右栏可显示“临时营地 / 火堆 / 金属锅#7 / 净水”。转移失败不清空原卡、不重置加工、不重复计算重量。

已被水煮预留的水禁用饮用与转移，并说明先取出对应原料以停止加工；空闲时取下加工锅仍按v0.4清空相关受热进度，操作条提前显示这一后果。不能因为改为内嵌展示而解锁原本被行动占用的实体，也不能仅因设施正在自动加工就永久禁止空闲玩家取出。

## 4. 点火：拖入工具或点按钮后选工具

### 4.1 拖拽入口

从随身或当前地面拖动有效打火器至指定火堆，松手后重新校验，通过即开始点火行动。不再打开一个需要再次按“开始”的预览页。

拖动悬停时，在右栏预览具体工具、火堆、5分钟耗时、身体数值预测、燃料变化，以及是否会自动投入1份木材。有效落点显示“松开后开始点火·5分钟”；非法落点显示原因并拒绝提交。

打火器松手即执行是本案对旧“耗时拖拽一律先预览再确认”的点火专用修订。普通制造、采集、移动的原确认流程不因此全部取消。

### 4.2 按钮入口

未燃烧的火堆在其UI下方直接显示“点燃”。点击后，在按钮附近打开点火工具选择次级菜单，不遮掉整条地块栏。菜单展示随身及当前地面的每个打火器：图标、名称#实例、来源、可用/不可用原因；已有耐久或状态信息时沿用实际数据。

**点击一把可用工具，即绑定该实例并开始点火，关闭选择菜单。** 即使只有一把也需要玩家点选；不自动选择工具，不在选择后追加“确认点火”按钮。悬停工具时右栏显示对应预测。菜单下方提示“选择工具后立即开始点火，耗时5分钟”。

没有可用工具时仍能打开菜单，显示“没有可用点火工具”及原因；不执行、不消耗。点击菜单外或按Esc只关闭菜单。已燃烧时不显示可执行“点燃”，保留既有熄火操作。选择列表不得出现其他地块的工具。

本版实际点火白名单仍为打火器。“点火工具”是UI类别名，不代表自动新增火柴、钻木取火等玩法。未来新增工具需在玩法配置中定义，UI复用本列表。

### 4.3 消耗、占用与失败

点火仍耗5个游戏分钟，打火器按现有规则不消耗。燃料为0且有可用木材时，沿用自动投入1木材、获得60分钟燃料的规则；没有木材则拒绝。燃料1—4分钟拒绝；剩余燃料满足要求时不强制另加木材。自动投木是既有点火规则，不恢复自动补水。

自动投木、工具锁定和点火开始必须在同一次玩法校验中提交，失败不得先扣木材。开始请求发出后立即防重复；同一requestId重复到达不能再扣资源或启动第二次。选中工具失效时提示重新选择，不暗换另一把。

点火完成才使该火堆获得加热资格，点火这5分钟不同时给刚点燃的火堆加热。0燃料自动投木时完成后剩55分钟；只有5分钟燃料时会在完成后耗尽，应在预测中明确提示。原来已燃烧的其他设施正常推进。

角色忙碌时遵循原占用规则：主行动执行中不能插入点火；主行动暂停时允许既有点火维护子行动，完成后原主行动仍暂停，等待玩家继续。设施自动进程在热源恢复后按v0.4自动续行，两者不能混用。

## 5. 全局鼠标滚轮规则

“所有菜单可滚动”指全部有溢出内容的菜单、卡片栏、操作列表和信息栏都能用滚轮到达内容；没有溢出的区域不需要产生虚假位移。滚动条与原拖动方式保留，滚轮作为同等可用入口。

| 悬停区域 | 普通鼠标滚轮 | 补充规则 |
| --- | --- | --- |
| 单行横向卡片栏、横向标签栏 | 向下滚→向右，向上滚→向左 | 包括相邻地图、第二行设施、地面、随身物品栏 |
| 纵向配方列表、人物信息、日志、工具选择菜单 | 向下滚→向下，向上滚→向上 | 右侧信息栏和所有现有次级菜单均适用 |
| 同时有横纵溢出的内容区 | 普通滚轮纵向；Shift+滚轮横向 | 给出可见横纵滚动条；不把普通滚轮同时应用到两轴 |
| 中部非卡片栏的空白/纵向容器 | 纵向滚动中部整体 | 窄屏时可到达两行地块栏和下方物品栏 |
| 触控板产生的原生横向/纵向输入 | 按原生方向 | 仅把纯竖向鼠标滚轮映射到横向栏；避免二次反转或放大 |

事件先交给鼠标下最内层、具有该方向溢出的容器；一次输入只由一个容器消费。内容未到边界时，不让父栏同时滚动。达到边界后，才允许未消费的输入交给可滚动父级：例如锅内纵向列表到底后可滚动中部整体，但不突然改成外层横向滑动。横向栏到边界时，可交给中部纵向滚动以避免困住鼠标。

轮滚在数量框上不自动加减数量、不改变下拉已选项、不触发物品使用；数量仍用输入和明确的加减按钮。Ctrl+滚轮保留浏览器缩放；不把它当作卡片栏移动。滚动、选中、开关菜单均不消耗游戏时间。

卡片被拖动时，滚轮仍可滚动目标栏，以寻找屏幕外的合法落点；拖动物保持跟随指针，滚动后重算热区，不能按滚动前坐标把物品放进另一张锅。需要拖到栏边自动滚动时可复用原能力，但不能代替本次滚轮支持。

当前选中卡在滚动后保持实例选择，不因卡离开屏幕而执行、移动或改选下一张。工具菜单滚动不得把鼠标松开错误解释为选择工具；执行需要一次明确的点击。

## 6. 取消左侧自身卡，人物信息进入右栏

### 6.1 右栏固定入口

左侧删除“自身”图卡、投放热区和相关提示，原时间、基础状态条、负重、目标、提示继续保留。原自身卡承担的使用说明、当前状态说明、人物详情统一进入右栏。

右栏顶部提供固定、始终可见的两个切换入口：**对象信息 / 人物**。它们与卡片下方“使用”按钮位置、文案均不同，不用一个按钮兼做查看和使用。

| 操作 | 右栏结果 | 是否执行玩法行为 |
| --- | --- | --- |
| 选中物品、地图、设施或内嵌内容图标 | 切到对象信息，展示该实例和可用操作说明 | 否 |
| 点击右栏“人物” | 展示基础属性、状态异常及已启用的技能等人物信息 | 否 |
| 点击“对象信息” | 返回仍有效的选中对象；对象消失则提示未选中 | 否 |
| 无选中对象时进入主界面 | 默认展示人物信息 | 否 |

人物页只展示游戏已启用的字段；v0.6若尚未采纳，不凭UI新增免疫力或战斗熟练度。左栏用于快速看状态，右栏人物页提供数值、解释、异常剩余时间；信息可以引用相同数据源，不能分别维护数值。

悬停具体操作时右栏临时展示预测，离开恢复原页签。主行动执行/暂停时，右栏固定行动区优先保留进度、危险原因和原有控制；页签只切换可浏览详情区，不能把“继续/取消”等行动控件顶掉。

### 6.2 取消原自身投放手势

原“把食物、水、绷带拖到左侧自身卡”的入口取消；不在左栏数值条、右栏人物属性或人物页签上建立替代投放热区。对自身使用统一走选中物品后的卡下按钮，避免把查看属性误判为服用物品。

拖物品到左栏或右栏普通信息区视为无效落点，原物归位，不产生使用、消耗或转移。若将来需要新增人物投放功能，另行设计清晰的专用目标，不恢复隐形热区。

## 7. 选中物品后的卡下按钮

所有允许对自身使用的真实物品，选中后在**该物品卡片UI下方**展示明确操作。地面、随身和可访问设施内容物采用同一规则；嵌套内容的按钮位于对应子卡/图标行下方，不把整口锅画成可以食用的对象。

| 对象例子 | 主操作文案 | 必须显示的预测/限制 |
| --- | --- | --- |
| 浆果、罐头、烤熟块根、水煮块根 | 食用1份 | 具体效果、5分钟及自然消耗、临近上限的溢出 |
| 散装净水或锅内未预留净水 | 饮用1份 | 500ml来源、补水效果、5分钟及自然消耗 |
| 允许饮用的脏水 | 饮用1份（风险） | 明示腹泻等既有后果，不把风险藏在悬停说明里 |
| 草药绷带等现有医疗物品 | 使用1份 / 包扎 | 既有效果、冷却、5分钟及自然消耗 |
| 其他已定义的自用物品 | 使用1份或更具体动词 | 由玩法白名单决定，不凭物品名称自行启用 |

普通材料、工具、空锅不出现无意义的“使用”按钮；仍可有转移、投料或放置等适用按钮。生块根、腐败食物、未制成药品的草药沿用现行不可直接服用规则；右栏说明原因，不因统一UI而允许直接吃原料。

对本来可自用但当前暂不可用的对象，保留禁用按钮并写明原因，例如绷带冷却、主行动占用、锅水被预留。当前地面和当地设施内的可访问成品允许直接按现有使用规则消耗，不强制先拾取；其他地块、未开放储藏或被锁定物品不可隔空使用。

### 7.1 操作条布局与执行

统一把选中卡的操作条置于卡下方，替代原随身转移条仅置于卡上方的差异。条内按“自用操作 → 转移目标/数量 → 转移执行”排列；可用宽度不足时操作条内部换行，不遮住下一张卡，不产生第二层物品详情页。

同一操作条只绑定一个选中实例，显示图标、对象名、来源和数量。自用默认1份；数量选择对转移生效，本案不新增批量连续食用。若玩家把转移数量调为2，食用按钮仍明确写“食用1份”，不能暗中吃2份。

选中卡片只展示操作，不执行；点击“食用1份/饮用1份/使用1份”就是该次使用的明确提交，不再要求到右栏按第二次确认。危险后果、耗时、溢出提示在按钮附近和右栏预览中事先可见；点击后重验来源、数量、状态、锁和冷却，通过才扣物及结算。既有特殊玩法若明确要求额外确认，继续按该特殊规则执行，不能用通用按钮跳过。

沿用现行非战斗使用结算：先扣1份并应用即时效果，再推进5个游戏分钟和对应自然消耗；关闭操作条不使用，连续点击不排队重复服用。物品已被移走或转化后，失效操作条关闭或更新到实际状态，不能按旧引用扣另一批。

“地面直接食用”和“拾取到随身”是不同按钮，前者不先临时入包，不受一次不存在的中间入包重量影响。整锅拾取仍严格校验锅与全部内容总重。使用来源为锅水时，只消耗所选锅的可用水，不自动向其他锅或散水补取。

如果日后启用回合制战斗：相同自用按钮必须经过战斗命令校验，不能调用非战斗5分钟使用路径绕过AP；按已采纳的战斗规则决定医疗物品的AP和可用性，战斗中禁止的食物/饮水显示禁用。本案不另行规定战斗数值。

## 8. 程序交接约束

1. UI保存唯一选中目标：目标类型、真实实例ID、完整owner路径；不按列表位置识别“第一个锅”或“第一个食物”。右栏和卡下操作条引用同一选中目标。
2. 将地图行与设施行拆成独立布局容器。当前地图固定可见，相邻地图子栏横滚；设施、地面、随身各自横滚，中部整体可纵滚。
3. 火堆与锅组件复用现有物品图标，不新增一个独立内容物页面状态。保留点火工具选择菜单、数量控件和转移操作条，但不得据此恢复内容物层级导航。
4. 点火拖拽和选择工具最终调用同一绑定指定工具的点火命令；食用、饮用、医疗分别走现有相应命令。前端不直接扣物、加状态或改owner。
5. 拖拽、点击转移、卡下自用等玩法请求沿用原幂等机制和执行锁；选择、菜单开关、滚动、页签切换只修改UI状态。
6. 工具列表、内嵌内容与预测随玩法状态更新；属性、消耗、物资数量不在不同组件里复制维护。转移后及时更新所有可见区域，保证实体只出现在真实所属位置。
7. 本次通常只需增加UI偏好/选择状态，不主动升级玩法存档。若程序实际需要迁移，必须明确迁移原因，不借本次UI修改更换物品owner模型或回退v0.4设施结构。

旧[策划增量配置v0.4](<../卡片统一与设施烹饪 v0.4/策划增量配置 v0.4.json>)保留历史内容，其`ui.layout`与`ui.facilityContentsPanel`已被本案替代；不要继续据此创建火堆覆盖菜单。其余未被替代的设施容量、时间、食品参数继续有效。本次没有制作可直接导入引擎的配置补丁，程序应将本案规则映射到实际UI实现。

### 8.1 旧界面清理清单

- 删除左栏自身卡、可投放提示和对应命中区；旧使用指引改为“选中物品，在卡片下方使用”。
- 删除火堆内容物和锅内容物逐层覆盖页面，以及对应返回面包屑、仅用于这些页面的Esc退层逻辑。
- 点火仍保留工具选择菜单；删除选中工具后的第二次点火确认和拖入工具后的二次开始按钮。
- 地图、设施不再因普通换行混排；保留物品图片、探索满进度隐藏按钮、清理次数恢复等既有设定。
- 卡片操作统一下置后，移除旧随身卡上方重复操作条；右栏保留详情、预测和行动控制，不复制一套拾取/放下入口。
