## 2. 关键解释与新增数值的身份

- “探索完成后无法再探索”按**当前地点探索度达到100%**解释，保留30分钟一次、每次增加25的四阶段结构；不是第一次探索后就锁死地点。
- 地图栏指当前地点的信息栏，不是世界地图中任意远端节点。清理只能在角色所在地点进行。
- 清理与探索共用**同一地点、同一概率、同一件数**的随机表，包括未获得物资的结果；只有清理扣清理次数。探索次数由剩余探索度限制。
- 定向搜集继续保留。随机散落资源与原资源点库存分开；捡到野果不自动发现野果丛。
- 锅容量1升、每地清理容量、恢复间隔及所有掉落权重是**本项目首版调参值**，不是声称复刻原作参数。
- 水量条表示容器装载比例，不是玩家的水分状态，也不是烧水进度。

## 4. 统一行动事务

### 4.1 开始

校验所在地、主行动占用、目标与材料 → 生成actionId → 锁定随机结果与配置版本 → 执行开始时扣除或预留 → 保存活动状态。

清理在此扣1次数，取消不返还。探索不扣清理次数；同一地点探索中不能再启动清理。烧水锁定锅及其内容，引用原物品，不复制物品。

随机结果在开始时产生并隐藏，完成才公布；读取同一活动行动继续使用已保存结果。UI预览显示可能结果和概率，不展示该次内部抽签。新行动推进随机状态，不因为关闭窗口、换入口或重启程序回退。取消后的重新行动是新actionId，不承诺与上一行动同结果。【实现同步】开始请求与即时操作都带 requestId，最近 32 条存进存档，重发同一请求只生效一次；随机数 r 取 floor(存档内 xorshift32 的 NextDouble × 100)。

### 4.2 每个5分钟段

1. 按段首状态计算本段倍率、身体消耗及0值伤害。
2. 推进5分钟世界时间，处理身体变化、各地燃料、原资源点午夜补充、清理次数恢复、物品到期。
3. 死亡优先终止；随后检查持续条件。烧水仍遵循v0.2“完整覆盖本段的最后5分钟燃料允许本段完成”的例外。
4. 增加有效工作量。满足完成条件且角色存活时，一次提交本行动结果。探索一次提交探索度、里程碑、随机产物与日志，任何一步失败不得只提交其中一部分。
5. 应用行动末尾伤害并判死，保存结果。低值提醒若恰好与行动完成重合，保留已完成结果，再提示身体危险，不制造已完成行动的暂停条。

未完成段末触发低值时暂停；继续、取消和补给子行动沿用原规则。取消在下一边界处理，不提交探索进度和随机物品。清理已经扣除的次数不退；其他已消耗世界时间和身体变化不退。

## 6. 接入顺序与总验收

先做唯一物品归属、锅内容与重量 → 卡片整理和转移 → 投料与装水 → 拖拽配方预览 → 清理次数与共享掉落 → 探索结果合并 → UI与存档升级。测试分别覆盖三份案的验收表。

上线本次原型前必须证明：物资不会因装水、取消和读档复制；清理次数不因切图或现实等待回复；探索100%不可再次刷物；相同地点的探索和清理引用同一张掉落表；所有新增操作不能绕过单主行动、所在地和负重限制。【实现同步】五条由 ContainerTests、ClearTests、ExploreLootTests、DropResolverTests、MigrationTests 与 SurvivalBot 七日通关覆盖（共 138 条测试通过）；浏览器实测见 doc/试玩记录 v0.1.md 第 4.1 节。本包未做：固定对象排序、筛选、触屏拖拽。
