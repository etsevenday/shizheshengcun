## 1. 容器结构与容量主表

只开放“地点固定火堆→锅→水/食材”，不开放锅套锅、建筑任意储物或背包嵌套。锅在地面/随身只存放，实际属于燃烧火堆加工位才能受热。

| 维度 | 当前容量/规则 |
| --- | --- |
| 锅水区 | 1000ml，按500ml整份转移；空0%、一份50%、两份100% |
| 液体类型 | 空/脏水/净水，不混净脏水，不自动倒出或替换 |
| 锅食材区 | 2份，各占1位；生块根、本锅水煮块根、生肉、烤肉、水煮肉 |
| 锅空重 | 1000g，另加真实水和食物；满水2根总2600g |
| 两容量关系 | 水和食材各自独立，满1L可有2食材；2食材不等于可装2L |

> 【实现同步 2026-10-27】锅食材区实际可从外面放入的是生块根和生肉（R06 已开启，M44 db4d4dd）；水煮块根、水煮肉只作为本锅熟成的成品留在锅里。配置白名单 `containers.pot.storedFoodIds` 列有 raw_root、boiled_root、raw_meat、cooked_meat、boiled_meat，但放入锅还要求该物品有锅内加工配方（src/Core/Engine/GameEngine.Facility.cs MaxPutFood→CanBoilInPot），所以水煮块根、水煮肉、烤肉都放不进锅，提示"没有可用的处理配方"。（已按策划 2026-10-27 答复 Q2 实现：烤肉、水煮肉可放进锅，提交 b6473cf，本注记作废）

腐败内容仍占位，等待玩家取出。完成熟食也保留占位。空锅可存根但缺水不加工；不自行干煎。R06已接入，生肉、烤肉、水煮肉可存入锅；烤肉有合法受热和净水时转为水煮肉，水煮肉仅存放。（【实现同步 2026-10-27】R06 已开启：生肉可放入锅水煮、放火堆直烤位烤制；实际能出现在锅里的肉只有生肉和本锅煮成的水煮肉，烤肉进不了锅，见上条。原文"肉类成品"与 R06 §3"生肉及本锅水煮肉"写法不一致，已列入待策划确认，见 00 总则/02 开发方待确认问题.md Q2）（已按 Q2 答复实现，提交 b6473cf，本注记作废）

## 2. 唯一归属与重量

锅入火堆后owner=facility:<id>，水/食物owner=pot:<id>；锅及后代不在地面/随身留副本。取整锅时后代全部随行，进入随身按合计重量校验一次。随身水装随身锅总重不变，地面水装随身锅增加水重。

火堆最多一锅的容量由S09负责；玩家明确放哪一口，不自动按锅位/随身/地面顺序挑锅。锅位满提示当前锅与内容，不能悄悄替换。

## 3. 操作契约

| 操作 | 结果 |
| --- | --- |
| 水拖锅装水区 | 扣源整份并加入该锅，容量/同种/锁校验 |
| 食材拖锅食材区 | 成为真实内容；满足条件后由S11处理 |
| 锅拖当前地面/随身 | 整锅转移，保留内容，关联进度按S11中断 |
| 锅内水/食物拖出 | 转移指定子物，不误取整锅 |
| 点击子物图标 | 选该实例，卡下选择数量与目标，执行后才转移 |
| 点击子物转移箭头 | 直接转移1份到随身，失败说明原因；不打开操作条 |
| 合法锅水饮用 | 卡下“饮用1份”，按S12费用，不自动换其他水 |

所有装入/取出/倒出到地面或随身均0游戏分钟，仍受忙碌白名单与负重限制。整次失败不改owner、不清热进度。显式锅热区失败不落父火堆。禁止自动补水，包括配方入口、进程缺水或半锅情况。

## 4. 锅内显示

锅主图、名称/实例、水量条、液体图标与数量、两个食材图标与进度直接出现在锅卡；火堆内也是同组件。内容物不靠再开子菜单查看，箭头直接转移，图标才负责选择。显示总水与可用/预留水，预留水不能因“仍在锅里”被饮用。

空锅明确0/1000ml与0/2食材，缺水/等待净化/加工中/完成/腐败用图标+文字。点击内容只刷新右栏与卡下操作条；不改变实体。容器卡与子卡起拖把手、滚轮和事件冒泡规则见S07/S14。

## 6. 本轮定稿：肉类存放与锅无耐久

Q2取代§1及R06§3的【实现同步】中“烤肉放不进锅”：烤肉可入空锅或有水锅存放，仅当锅在燃烧火堆、有效净水足额时按S11受热转成水煮肉；不因单纯存放或现实时间流逝转化。水煮肉可从外部重新放进锅存放，不要求额外加工配方、不再转化或耗水；腐败物不因入锅恢复。外部水煮块根是否可存入本次不扩展。

P02取代§5及对应【实现同步】的锅耐久/维护：金属锅没有耐久，无磨损、无维护不足状态、无锅修理按钮；保留全部容量、重量、内容物、水预留和受热条件。其他工具耐久不受影响。

Q5-2/Q11已确认：锅内水/食物或设施内整锅箭头直接取1份/1实例到随身，不弹操作条。锅已在随身时，子物仍从锅取为独立随身卡，不默认放地面；总携重不变，锅水量/真实owner按数量原子更新。预留、占用与所选来源校验仍适用；转移失败不改进度/owner。需要地面或其他数量时点击内容图标，明确目标后执行。采纳下方【实现同步】对应箭头做法，原文保留。

> 【实现同步 2026-10-27】Q2 已实现（提交 b6473cf）：从外面能放进锅的为生块根、生肉、烤肉（有锅内复煮配方）与水煮肉（只存放，`containers.pot.storeOnlyFoodIds`）；水煮块根仍只作本锅成品，外部不能放入。烤肉在燃烧火堆上的锅里、预留净水500ml时按 S11 §8 复煮。Q5-2 已实现（提交 baa1d80）：火堆里的整锅与锅内食材箭头直接取到随身，锅内水箭头取1份到随身；锅在随身时，锅里水的箭头同样“取1份到随身”，即从锅倒成一张随身水卡，总重不变（开发计划 v0.6 开发假设 16，是否改为放到当前地面见[开发方待确认问题](<../00 总则/02 开发方待确认问题.md>) Q11）。

本轮联动（2026-10-29）：整锅及内容占一张根卡，取出内部物品成为独立随身根卡时需S06 §8容量重验。随身已五张且不能合法合堆时，Q11箭头拒绝并显示卡位已满，不因总重不变跳过检查。锅内操作窗按S14 §18.3悬浮，不撑高设施/随身行；真实内嵌内容仍可见，不恢复层级详情菜单。

Q16联动：锅内新鲜食材实际有效受热后取得的保护绑定其真实实例/进程；仅存放、装水或预留不保护。取整锅/食材成功时按S11清相应进度与保护，过原期限者立即腐败；五根卡满/超重/占用失败不先解除保护。完成复煮成品从完成起24小时，成品存放不刷新，水煮肉不重复加工。
