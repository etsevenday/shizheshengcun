### 边界、迁移与失败

1. 两类自动触发可以在同一边界同时发生，各写自己的槽；若已在空闲边界则立即写，若正在提交则等待完整事务结束。保留原终局、段结算与幂等顺序。每日槽绑定实际 06:00 段的快照，不用后续世界段冒充当天 06:00。现实槽错过多个间隔只写最新一份。两类触发的计时、世界日与待保存目标分别管理。
2. 各槽成功写入后才更新列表摘要。使用独立持久化键与原子替换，一次失败只影响目标槽，旧成功内容继续可读。容量不足沿 Q282「存档失败：浏览器存储空间已满。」和「重试」，重试写原槽与对应快照；自动槽的失败按槽保留并依次处理，手动失败按 Q406 留在子页。同槽较新的到期任务覆盖较旧未落盘任务。临近读取、重开或换页时，旧回调不得写入新局。多标签页的写入与接管见 Q381。

**Q381 多标签页写权限。** 最近一次成功进入本局（新游戏或读档）的页面持有写权限。打开标题或存档选择页不抢权限。旧页面立刻停止自动、手动、「保存并返回标题」和重置地牢写入，失权期间已排队写入暂停、旧派发回调失效，逻辑任务与计时按 Q408 保留并在成功接回后恢复。底栏常驻「另一个游戏页面正在保存。」，后接「在此页面继续保存」。手动存档、「保存并返回标题」和确认重置在无权限时禁用，原因同底栏。点击接回时，以本页最后确认持有写权限时所见的各槽版本为基线重验。有任何槽已保存较新快照时不接回，底栏提示「另一个页面已保存了更新的进度。请返回标题重新读取。」。玩家可刷新页面回到标题，未保存的进度按 Q388 提醒。校验通过才转移权限，随后按 Q408 恢复原任务与计时。权限和目标版本检查与实际写入串行，避免旧页面异步写入覆盖新页面。无权页面可以退出浏览器，未保存的进度仍按 Q388 提示。

**Q382 终局。** 主角死亡或尸变首次提交终局时，将完整结算状态立即写入「自动存档 · 每5分钟」一次。已排队的该槽旧快照不得盖过终局快照。失败保留原槽，按 Q282、Q387 提示并重试本次终局快照。终局提交后停止自动计时和其他未落盘的自动任务。终局段不另外触发每日自动档。读取已结束的存档可回看结算，读取本身既不启动定时器也不覆盖任何槽。

**Q383 旧单槽导入。** 打开游戏页面时静默尝试将旧单槽经现有迁移链导入每5分钟自动槽。只有新槽快照已写入、可完整读回并校验通过且成功标记已导入后，才删除旧主键和 .bak。导入不覆盖多槽系统已存在的较新快照。重复打开不重导已完成的迁移。失败时保留旧主键和备份原样，在「自动存档」区显示「旧版存档」，原因「这份旧存档无法升级：{原因}」，「读取存档」禁用。如果是因为新槽已存在而无法导入，原因写「每5分钟自动存档中已有较新的进度。」。标题页取消升级预告。导入后的首次升级提示按 Q410 判定，原版本42的档静默，其余确有升级的导入档只提示一句。

**Q384 存档选择。** 标题页「继续游戏」始终可点。选择页用「自动存档」「手动存档」分区，排序和卡面字段沿上节。没有可读档时写「还没有可读取的存档。」。损坏、版本过新或迁移冲突的槽仍列在所属分区，类型行下显示「这份存档无法读取：{原因}」并禁用该档的「读取存档」。旧单槽导入失败专用 Q383 的原因句。单槽异常不阻断读取其他档。

**Q385 手动存档。** 入口位于普通游戏菜单，子页标题「手动存档」。战斗、待处理敌踪和死亡结算菜单不提供入口。支持新建和明确覆盖，覆盖确认及安全重验沿上节。手动档没有删除或改名入口。普通菜单显示实际的禁用原因，按下表由上到下只显示第一条命中的原因。写权限丢失时执行 Q381 的专用提示。本批菜单可达场景中的在办事务按 Q411 仅指招募待安置。事务确认窗按原遮罩处理。未锁操作的岗位接续待补播（Q243）不算在办。

| 阻断条件 | 原句 |
| --- | --- |
| 强制对白未读完 | 请先读完对话 |
| 战斗中 | 战斗中不能手动存档。 |
| 旧版敌踪待处理（仅B41上线前） | 先处理敌踪再存档。 |
| 撤出中 | 撤出途中不能手动存档。 |
| 主行动正在推进或子行动在办 | 行动进行中，不能手动存档。 |
| 主行动暂停 | 行动暂停中，先继续或退出行动再存档。 |
| 强制整理未完成 | 先完成整理再存档。 |
| 招募待安置 | 先办完当前事务再存档。 |

子页内成功写「已保存到手动存档。」，失败按 Q282 和 Q387 显示并可重试。重试仍要通过安全空闲、写权限与目标槽版本校验，避免覆盖其间更新的档。

**Q386 新局与读档。** 普通游戏菜单保留「重新开始…」，与标题新游戏和终局重开共用上节的确认文案及「开始新游戏」「返回」。只写新局初始快照到每5分钟槽。局中没有读档入口，使用「保存并返回标题」回标题后，从「继续游戏」进入存档选择。

**Q387 时刻、失败与返回。** 普通游戏菜单在「存档保存在当前浏览器。」下列三行：「每5分钟：{本地日期时刻}」「每日06:00：{本地日期时刻}」「手动：{最新一份手动档的本地日期时刻}」。未写入的值用「尚未保存」。已有快照的时刻缺失用「保存时间未记录」。读取槽本身失败时，该行按 Q413 写「尚未保存」。底栏成功状态写「已保存 {本地时刻}」，使用最近一次实际保存成功的时刻。后续操作未落盘时不刷新此时刻。失败句前标目标槽，如「自动存档 · 每日06:00：存档失败：浏览器存储空间已满。」后接「重试」。其他异常仍用现有失败句。多个自动槽的待重试项依次展示，手动存档失败按 Q406 只留在子页。失权与失败同存时按 Q408 展示。「保存并返回标题」成功写入每5分钟槽后结束本会话，其他槽尚未执行的写入和失败提示一并清除，已成功的快照仍可读取。此次写入失败则留在当前画面并显示失败。

#### Q404 不可读卡与旧版卡

不可读槽仍显示其所属类型和原因。现实保存时刻、游戏日和时刻、地点及「本局已结束」等字段，只显示能可靠读出的值，缺失字段省略。旧版存档卡的现实保存时刻固定写「保存时间未记录」，其余能读出的字段照常显示，排在自动存档区最后。其他档的排序沿 Q335。

#### Q405 手动存档子页

已有手动档整条可点击，点击只进入覆盖确认。条目同时支持键盘聚焦及回车／空格激活。子页「返回」回到游戏菜单。

列表及覆盖确认摘要与存档选择卡相同，显示类型、现实保存日期时刻、「第{世界日}日 · {时刻}」、地点，已结束的附「本局已结束」。列表按成功保存时间从新到旧。类型均写「手动存档」，通过日期和摘要区分。

不可读取的手动档也可点击进入覆盖确认，显示可读摘要和原因，缺失字段按 Q404 处理。覆盖时仍显示「覆盖这份手动存档？」及「确认覆盖」「取消」。确认前重验写权限、安全空闲与目标槽版本。覆盖失败时保留原槽。

#### Q406 时刻与底栏

卡面和菜单的现实日期时刻按浏览器本地格式显示年月日及小时、分钟。底栏成功时只显示「已保存 {时:分}」。读取存档后，本页尚未成功写入任何槽时，底栏保存状态留空。读取到的历史保存时刻仍可在卡面和菜单查看。

手动存档失败只在子页显示，当前子页可重试。离开子页时清除该次失败提示和未执行的重试任务，原槽保留，上次未保存的游戏进度仍按 Q388 判断。

所有写入失败均标明目标槽，包含非配额失败。自动档例如「自动存档 · 每5分钟：保存失败：{现有错误正文}」，手动档子页例如「手动存档：存档失败：浏览器存储空间已满。」。Q403 专用于不可读卡和旧单槽导入原因，日常写盘失败继续按 Q282、Q387 分支给实际原因。

#### Q407 存档地点

地点取所选快照中的当前实际地点名，与品牌行取名一致。移动途中用起点，安全屋内用地点名，已结束档用死亡或尸变发生时的地点。不可读档能取出地点时仍用同一规则。

#### Q408 多页面接回与任务恢复

- **Q408-1 选 A。** 接回因存在更新快照而被拒绝后，以拒绝句替换失权句并常驻，隐藏「在此页面继续保存」。
- **Q408-2 选 B。** 失去权限时暂停所有写入，保留本会话各槽原待写快照、待重试状态和原计时。旧的已派发回调失效，接回后由新取得的写权限继续调度这些逻辑任务。接回仍先通过 Q381 的各槽版本校验，任一槽有更新则不恢复写入。
- **Q408-3 选 A。** 手动存档同时命中失权与其他安全阻断时，先显示写权限原因。
- **Q408-4 选 B。** 底栏先显示失权句或拒绝接回句，再依 Q387 显示各槽失败信息。失权期间「重试」禁用，原因「另一个游戏页面正在保存。」。接回成功后去掉写权限提示，恢复原待重试项的正常条件校验。

恢复原计时指保留从进入本局开始的现实时间轴。失权期间写入停止，经过的现实时间仍计入原周期。接回时已超过一个或多个 300 秒周期，按 Q335 只请求一次最新现实快照，下一到期点沿原时间轴计算。仍未到期则继续等原定时刻。待写每日槽仍绑定原来实际跨过 06:00 的那份快照。失败待重试项仍由玩家重试，已到期自动任务按可序列化边界继续。同槽新到期任务替换旧任务仍按 Q335 边界 2，串行调度并重验权限、局身份和目标版本。

#### Q409 计时、新局确认与终局失败

1. 地牢重置、手动存档等额外写入成功后，保留原 300 秒周期。主角终局仍按 Q382 停止自动计时。

## 1. 目标与边界

地图、探索、清理、采集、制作、休息与设施共用一个世界时钟。本系统规定“何时扣费、何时完成、如何暂停和恢复”；各玩法只维护自己的结果，不能另开一套身体消耗或真实时间定时器。

## 2. 时间与工作量

| 参数 | 基础规则 |
| --- | --- |
| 绝对时间 | 第1日00:00为0，开局08:00为480分钟 |
| 结算步长 | 5个游戏分钟；00:00换日；06:00—18:00白昼 |
| 离线/浏览 | 不推进世界时间；排序、转移、投料、装水不耗时 |
| 工作动作 | 移动、探索、清理、采集/搜集、制造、建造 |
| 固定时长 | 等待、休息、睡眠、自用物品、点火；不应用工作倍率 |

> 【实现同步 2026-10-27】工作动作另含处理尸体、工具维护，同样吃工作倍率（config `actions.workActionTypes`，src/Core/State/GameState.cs `IsWork`）；遇敌踪“绕行”固定10分钟、按移动速率消耗，不应用工作倍率（config `encounters.bypassMinutes`、`bypassRateCategory`）。

每段工作量增加`5/M`，世界时间增加5。`M=min(2,夜间系数×负重系数×低体力系数)`：无照明夜间1.5，携重>20kg为1.25，体力E<4为1.25（【实现同步 2026-10-27】实际为体力E<4（不含4）才×1.25：config `thresholds.energy` = 4、`stateScale.lowEnergyExclusive` = 4；R01 已开启，H/E 上限 20、新局 E=18），其他为1。每段用段首条件重算；不足一段也结算完整5分钟，不把余量送给下一次行动。

移动始终视为无照明；其他工作在当前地点有燃烧火堆时免夜间系数。室内不自动有照明。工作时间变长，身体按实际流逝时间消耗；设施受热不应用角色倍率。

例：20基础分钟，M持续1.5，需30世界分钟；M持续1.953125需40分钟。当前采用小数值，低体力线为4，见[R01 人物属性、熟练度与数值尺度](<../02 参考扩展/R01 人物属性、熟练度与数值尺度.md>)，不能只修改UI显示。

## 3. 行动状态与占用

单角色最多一个主行动和一个补给/维护子行动，不做子行动栈。

| 状态 | 可浏览/排序 | 实体操作 | 可开始的耗时行为 |
| --- | --- | --- | --- |
| 空闲 | 是 | 通过所在地、负重、容量和锁校验后允许 | 正常主行动 |
| 主行动执行中 | 是 | 禁止实体转移、装水及材料替换 | 不另起行动；允许申请段边界取消 |
| 主行动暂停 | 是 | 仅原有补给、燃料维护白名单 | 补给、休息、点火维护子行动 |
| 子行动执行中 | 可查看 | 禁止 | 不再嵌套；结束回原暂停态 |
| 死亡/最高层弹窗 | 按该层规定 | 禁止 | 不可继续游戏行动 |

> 【实现同步 2026-10-27】内核允许暂停中开始自用补给、休息、点火三类子行动（src/Core/Engine/GameEngine.cs，拒绝文案“暂停中只能补给、休息或点火维护”），但暂停层（web/Survival.Web/Components/PauseLayer.razor）只有随身补给按钮和“休息30分钟”，没有点火入口，且盖住中部地图/设施行，玩家实际无法在暂停中点火；列为开发计划 v0.4 第7节第6条待确认。（已按策划 2026-10-27 答复 Q5-3 实现：暂停层增加点火入口，提交 baa1d80，本注记作废）

> 【实现同步 2026-10-27】v0.6 另有“敌踪待选/战斗中”状态：此时内核拒绝世界交互、拖拽与即时操作，只能选择接敌或绕行、或下战斗指令（开发计划 v0.5 开发假设7，见 R03、R05）。

移动途中仍位于起点，但不能使用起点/终点地面物资；暂停只用随身补给，休息按露天，不能点火或整理物品。实体转移禁用时，UI排序不得趁机改变owner。

## 4. 开始、推进、提交

开始：重验所在地、占用、库存、材料、工具、容量与风险→生成actionId→保存配置快照/隐藏随机计划→扣开始费用或预留→保存。清理次数开始即扣，资源库存和制作材料按各系统预留；自用物品先扣物应用效果后推进5分钟。

每段按以下顺序接入现有统一tick：

1. 读取段首身体、时间、地点、燃料和加工快照，计算倍率、身体变化与归零伤害。
2. 世界推进5分钟，更新身体、燃料、午夜资源补充、清理恢复、物品到期。
3. 先判健康死亡。死亡时停止，当前段尚未提交的加工与主行动产物不补发。
4. 按[S11 设施加工与烹饪系统](<S11 设施加工与烹饪系统.md>)提交合格设施进程，更新角色主行动工作量及持续条件；持续条件失败按对应系统暂停/终止。
5. 主行动达到目标且有效时一次提交结果；探索的进度、解锁、物资、日志不能只提交一部分。
6. 若该行动有末尾受伤，先提交该行动产物再结算伤害并判死；低值与完成重合时保留完成结果，不留一个可重复领取的暂停行动。保存。

> 【实现同步 2026-10-27】v0.6 接入后统一 tick 的实际顺序为：段首快照→火堆燃烧与身体变化（含药物时间、免疫、病毒）→健康归零死亡、尸变判定→自然治愈→清理次数恢复与跨日→设施进程→世界敌人刷新与巡游；之后才累积主行动进度、提交结果，探索/清理提交后再检查随机接敌（src/Core/Engine/GameEngine.Segment.cs `WorldTick`）。战斗每轮末也调用同一 tick，每段只结算一次。

第4步的设施边界必须采用段首燃料覆盖完整5分钟的判定；本段刚净化的水下一段才给依赖它的食材受热。具体进程、取出和腐败优先级由S11维护，不能按界面枚举顺序随意结算。

## 5. 暂停、取消和重复请求

阈值规则由[S12 基础状态、饮食与医疗系统](<S12 基础状态、饮食与医疗系统.md>)维护。暂停保留原主行动进度、预留和隐藏结果；子行动不得覆盖。子行动不会再次弹出嵌套暂停，结束后统一提示；完成补给/点火后仍需明确继续主行动。

取消在段边界处理；时间与身体消耗不退。移动不更新地点、探索不加进度、清理不退次数；采集释放库存预留且不磨损工具；手工制作解除预留并按原规则返还材料到当前地面。设施加工不是主行动取消的一部分，停止方式见S11。

所有开始与即时操作带requestId，最近32条随档保存（【实现同步 2026-10-27】实际随档保存最近128条：src/Core/Engine/GameEngine.Instant.cs，v0.6 接入时扩大，开发计划 v0.5 开发假设6）；同请求重发只生效一次。随机由存档PRNG产生；清理/探索的r为`floor(NextDouble×100)`，开始锁定、完成揭示，预览不抽签。同一活动行动读取不重抽，取消再开始则是新行动。

## 8. 对话等待与记录持久化（本轮新增）

Q10已确认读完对话后才能操作。对话展示在当前原子事务完成并保存后的安全边界，不切断一次扣费/命中/掉落/轮末tick。存在后续自动推进时，在下一段/下一条战斗动作开始前等待对白完成；等待、翻页、回看不推进时间、身体、燃料、病毒或设施进度。界面覆盖不等于取消主行动、脱战或启动补给子行动。

进入时保留原行动/战斗ID、状态、进度、预留、AP、队列游标和随机计划。对话结束后释放对话输入锁，恢复之前允许的状态：原暂停态仍暂停、原战斗仍在原轮次、原执行流程只从下一合法推进点继续，不补tick、不重扣或重发。最高层确认框与对话串行展示，终局优先，不能靠结束对话复活。此节取代本案§7【实现同步】中“对白显示时不阻断其他浏览与操作”的口径，原文保留。

同一存档保存对话事件ID、台词ID/顺序、实际展示的发言者/正文快照、左右归属、对话发生的游戏内日期时间/地点、已展示游标、是否结束及待显示队列。每条首次展示与推进游标一同保存，以“对话事件ID+台词ID”去重；读档恢复当前已展示流和待读位置，不将未读台词标成读完，不重新触发剧情效果。只改了后续台词文案时，不倒改本局已经展示并归档的历史正文。

“继续/结束对话”和历史浏览不调用奖励、战斗胜利、融合或世界tick；剧情唯一事件仍按原归属提交。历史记录属于本局，新游戏确认覆盖时一同重置。已有存档若保存了可确认的已展示台词，可按原序一次性兼容为记录；无法确认展示过的内容保持空缺，不猜补、不重播、不解除Legacy边界。旧档没有新记录字段时按空记录兼容，保留全部原世界状态；存档schema如何升级由程序选择未占用版本，本文不指定版本号。

保存失败沿用§6失败反馈与重试；重试只补保存同一记录/游标，不重复展示、发奖或推进时间，不假报“已保存”。

## 9. 主动时间推进的退出与剩余时间（本轮新增）

所有主动持续推进时间的入口必须可随时请求“退出”。接收请求后停止调度后续段，若一个5分钟原子段已经开始，则完整提交该段后退出，不结算下一段；不能为播完动画额外跳段。未开始的事务可取消且不扣费；已提交的开始费用、即时效果、世界时间、身体消耗与成品不回滚。取消工作仍按§5及对应玩法处理材料/库存预留；取消不是只收起中央条或后台继续推进。死亡、同段完成与取消重合时先按既有提交/判死顺序确定结果，不产生重复奖励或复活。

Q14已确认：点火、自用、融合在开始即提交扣物/耐久/即时效果；开始后没有可撤销空档，退出只停止后续推进安排，当前5分钟段必须正常结算结束，效果与费用不退。明确显示“已开始结算，本段完成后结束，已提交效果不撤销”，不声称可在淡入期间撤回。尚未提交的预览可关闭；多段工作仍在段间受理退出，不因跳过动画一次把全部时间同步算完。子行动结束仍返回原主行动暂停态，不解除父占用。取代本节旧单段段前撤销正文，采纳对应【实现同步 2026-10-28】现状。

中央条由S14 §11展示，剩余时间是游戏内时间。固定时长按未发生时长；工作按剩余工作量/当前与已知未来倍率逐段估算，向5分钟结算边界取整；条件变化时重算并标“预计”。只读估算不推进时间、不消耗燃料、不抽未来随机。被动设施热进度可在卡内展示，右栏不再放主动执行进度。

“等待烹饪”复用S13等待主行动，每段只调用一次统一tick，目标/停止规则见S11 §9。保存其火堆、目标实例/进程链、已完成目标、已流逝时间、预期剩余及退出请求；读档按真实进度重算剩余，不重置热进度或恢复已经退出的等待。保存失败沿用§6，可重试保存同一结果，不重新运行已提交段。

退出后回可进行其他操作的空闲态；若原主行动因危险仍处暂停或处在战斗/剧情输入锁，则按该状态恢复，不能靠退出中央条脱战或跳过未读对白。战斗AP指令、敌动作和强制轮末tick保留R03事务，不新增任意中断/撤销。
