# 文案设计归属与修改规则

生效日期：2026-11-16。由本项目文案策划 shioko0315 明确设定：所有文案相关内容由文案策划负责，其他策划和开发不得擅自修改其设计；文案有问题，必须先向 shioko0315 提问，由本人确定。

## 适用范围

本规则覆盖世界观、正典设定、主角与全部 NPC 的人物小传（包括饱饱）、人物关系、故事大纲、主支线剧情、任务叙事、对白、旁白、档案，以及物品、技能、敌人、地点的命名与描述、界面提示和其他玩家可见文案。相同内容存于策划案、配置、代码、网页或其他载体时，均适用本规则。

其他策划、开发及代表这些岗位工作的自动化工具，不得自行改写、删减、扩写、替换、重新定稿或改变文案设计的含义、口吻与呈现文本；发现错字、表述不清、设定冲突或实现限制，也须先提问，不能以修错、精简、补全或实现同步为由直接修改。

## 发现问题后的处理

1. 保留原文，指出具体文件、章节或文本 ID，并引用有问题的原句。
2. 向 shioko0315 说明问题和具体触发情境；必要时给出候选改法及其影响。候选内容必须标为建议，不能写入正式文案或上线文本冒充定稿。
3. 等待 shioko0315 明确裁定。未答复、未读、待定，以及其他岗位的同意，都不能视为文案策划确认。
4. 按 shioko0315 确定的内容落实；开发可以原样接入已确认的文本，但不得在接入时再自行改写。若仍需调整，重新提问。保留原有文本 ID、历史记录与开发方维护的【实现同步】记录。

涉及玩法、数值和技术的问题仍按原有职责处理；若处理方案会改变文案设计或玩家可见文字，文案部分仍须先由 shioko0315 确定。

## 与既有约定的关系

本规则取代此前允许其他策划、开发或其自动化工具自行决定、精简或补写文案的宽泛授权，包括总纲中“纯措辞精简无需再逐处提问”“玩家文案由总控直接给短定稿”等表述，以及以【交开发方定】为由自行拟定文案的旧授权。历史正文和记录原样保留，今后文案修改以本规则为准。

本规则不撤销已确认的历史定稿，不代答任何尚未确定的开发问题。后续授权以 shioko0315 本人明确给出的具体范围为准，不能从一次确认推定其他文案也获准修改。

这是项目协作与审核规则；它本身不改变 GitHub 的账号权限或分支保护设置。
