## 1 已确认口径与未定边界

用户2026-10-30已明确答复并授权融合后上传：Q23保护中已过原期仍可吃（须本来可食）；Q24同物品按到期升序视觉堆叠但保留真实批次/五格；Q25攻击后收起；Q26未解锁招式操作台/当前指令说明隐藏；Q27整理默认不选；Q28全类卡图目标70%。来客D5 08:00且首战胜利；地牢与招募均72世界小时，非72小时；营外专用地块及所有非势力普通野外允许建安全屋，公共城内服务/实际势力占地/地牢内部不属于此许可。鉴定交易改有界随机以物换物，不开高品质随机词条；已有其余建议初值批准为可调实装，未定义仍待定。

已确认规则按各案执行；已有建议初值按本轮批准作为可调实装参数，不把建议值当永久定稿。仍无明确值的字段不能自行猜填；真实规则冲突回报具体文件/章节和最小复现，独立不受阻部分继续推进。旧实现注记和历史修改记录是原提交证据，不能因上传文档写成已实现。

## 2 阅读与分类开发顺序

先读[分组开发总说明](<00 分组开发总说明.md>)→[分类文件与逐案说明清单](<02 分类开发交付清单.md>)→当前批次主案/数据与各案更新说明。按B0共同基础、B2物理图、P0/B1任务接续、B2供给、B3服务、B4远征、B5 UI依赖分批；同主题跨文件应同时对齐，不能只改一份表。无须为逐分类实施拆成多次策划提交。

每批先实现本领域，再跑对应主案验收和下面相邻领域自检，修复后复验；每批交付附开发提交、实现同步、自动化结果及必要实机证据。不能以“本分类单测通过”替代跨系统验证。

## 4 每批开发回报格式

| 字段 | 内容 |
| --- | --- |
| 批次与代码提交 | B/P分类、实现commit、运行配置/存档schema映射、实际部署版本（若已部署） |
| 已实现规则 | 主案章节、逐案说明与验收ID；新旧取代范围、仍未实现部分 |
| 自动化证据 | 实际命令、运行环境、测试数/通过失败、失败日志；没有运行就写未运行 |
| 兼容性自验 | COMP编号＋前置存档/seed＋操作步骤＋期望＋实际＋结果，回归受影响邻系统 |
| UI证据 | 三档分辨率/场景/版本截图与点击验证；示意图和元素检测不能冒充视觉复验 |
| 迁移证据 | 新旧档、已领奖/已开路、混批/满包/锅进度、写盘失败/重复请求对照 |
| 平衡观察 | 真正远征耗时、食水/睡眠、卡位重量、可重复收益；不把静态预算标成实测 |
| 偏差与修复 | 失败原因/修复提交/复验结果；确实需策划裁定的问题单列，未通过不写已完成 |

开发方在既有开发计划及对应案【实现同步】中据实记录实现/测试证据；不要删除旧注或覆盖原修改记录。策划当前文档检查只证明引用与规则整理，不保证新程序兼容性已成立。
