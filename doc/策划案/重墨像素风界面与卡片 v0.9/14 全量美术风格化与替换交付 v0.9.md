## 文件与图层合同

1. `svg/item/`、`svg/skill/`、`svg/resource/`、`svg/facility/`、`svg/status/` 等按类别和 ID 存放透明 SVG。32 格小图使用墨色轮廓、材质亮面和细节组；常规卡片显示 48–96 CSS px。边框 96 格、透明中心、四边各切 16 源单位。SVG 底纹等比平铺。
2. `art/` 包含 13 张新增图集。清单的 `file`、`size`、`crop=[x,y,width,height]`、`portraitCrop` 均为原图像素，原点左上。人物和敌人保持透明；地牢背景为无字矩形。可直接读取图集，也可运行 `导出单图.ps1 -Destination <空目录>`，得到按 ID 命名的立绘、肖像、敌人战斗图与地牢 PNG。导出裁窗保持原像素，无需重新生成。图集路径、生成提示、透明属性与哈希见 [生成图集](<assets/全量素材库/生成图集.json>)。
3. 统一色板以近黑 `#13120f`、铁褐 `#755c3f`、骨白 `#e8d7b2` 为主，暖金用于选中，青钢用于合法落点，红锈用于危险。危险、禁用、进度与选中继续同时提供形状或文字；品质以真实标签区分。
4. 层序为场景、主体、底纹、边框、状态、文字。菜单和对白额外使用独立遮罩；对白头像、姓名、正文滚动区和继续分离。通常对白沿原两轨覆盖，战斗对白用战斗层；历史独立只读。图层切换保留容器位置。控件的焦点、点击和返回沿现行合同。
5. 字体使用 Q275 的缝合像素简体中文版比例版，附拉丁混排。同包提供原版 WOFF2 及发行包授权文件。常规 8 格字模用 16 CSS px，长对白 10 格字模用 20 CSS px，标题 12 格字模用 24 CSS px。预览验证本地加载，开发按 Q275 核对游戏全量动态字形。字库来源和哈希见 [字库来源](<assets/全量素材库/字库来源.json>) 与 [上游发行](https://github.com/TakWolf/fusion-pixel-font/releases/tag/2026.10.25)。
6. `角色合成.mjs` 演示如何用已保存的肤色、发型、发色和面部细节绘制人物和头像。相同输入得到同样图形，缺字段只取中性部件。接入后用稳定人物身份缓存，跨名册、战斗、对白和读档一致。手持图形是造型样件，实际穿戴与手持视图仍由真实装备决定。

## 给开发的替换顺序

- 先按 UX2-B1 接公共底纹、边框、按钮、HUD 状态及正式像素字。拿净水、火堆、长对白和菜单做试接，验证键盘焦点、图层占位和禁用原因。
- 在 B2–B4 按清单的稳定键接整备、战斗、制作和城市。资产表只负责视觉路由，动作、费用、状态机、坐标和文字仍从原数据取得。确认替换主体或主题时游戏逻辑、选中状态和存档引用完整。
- B27c 文档卡复用已有文字逻辑。Q269 暂停与推进用原真实原因，Q270 不可读卡片悬停仅展示标题和当前状态。Q271 资源点按真实实例和已保存的掉落结果显示，资源插画不从素材键推断产物。
- B5 逐项核对 42 种敌人、各固定身份、各岗位代班、随机人物和所有运行时图位。重点检查图像朝向、足底、轮廓差异、标签不裁切、像素字缺字和旧档外观复现。使用 [07 原验收](<07 UI重做验收与实施 v0.9.md>)、INK2 和已答 Q，补实机截图、版本和授权记录。
