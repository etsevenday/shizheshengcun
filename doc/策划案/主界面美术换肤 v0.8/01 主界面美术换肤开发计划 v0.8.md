# 主界面美术换肤开发计划 v0.8

日期：2026-10-28。交付对象：开发方。状态：开发范围已确定，待实现与实机验收。本文是策划侧开发要求，开发方在自己的开发计划中记录实际实现、偏差和验证结果。

本轮把整个游戏主界面统一换成用户所给参考图的废土手绘风格，一次性交付可玩的主界面。开发步骤可以分段、分提交完成，各阶段自检后连续推进，不要求策划再逐屏确认。只改背景颜色、只完成五金店一张页面、只提供静态效果图，都不算完成。

正文与[S14 主界面与全局UI交互系统](<../系统策划总册 v1.0/01 基础系统/S14 主界面与全局UI交互系统.md>)配套：本文维护本次美术范围和交付步骤，S14继续维护布局、信息、交互和输入层。[验收清单](<02 主界面美术换肤验收清单 v0.8.md>)是本次完成判据。

“整个主界面”覆盖现有全部地点和所有能在以上区域出现的对象，不以参考图的地点和背包内容作为范围上限。已接入但当前截图没有的药品、弹药、尸体、活性物质、敌踪等也纳入对应卡片样式与图标盘点。

区域地图、制作、休息、日志、目标、提示、对话记录、系统说明、菜单，以及战斗和对白，**本次不重新设计专用布局、正文或角色造型**。它们使用到的共用卡框、字体、按钮、面板随主题一致更新，必须完成兼容回归；不能把其完整美术重制变成本轮前置条件。已有主角、饱饱、敌人形象的内容含义不变，后续专用插画另批安排。

## 3 统一视觉规范

### 3.1 色彩与材质

以下是制作初值，开发方可根据实机对比调整明度和纹理密度，无需逐个色值请示；不能改成另一种美术方向。

| 用途 | 初值 | 使用要求 |
| --- | --- | --- |
| 环境底色 | `#101719` | 墨黑偏冷，废墟轮廓低对比，正文区不用高频杂线 |
| 深色信息面板 | `#1B2223` | 与环境分层，正文下面有稳定衬底 |
| 旧纸卡面 | `#D5C396` | 米黄旧纸，物件轮廓清楚，局部磨损不穿过文字 |
| 主要行动 | `#DDAE55` | 暖金底与深色字；不要把所有面板都涂成高亮金色 |
| 次要边框 | `#8E754A` | 细窄、低亮度的旧金属边缘 |
| 深底正文 / 纸面正文 | `#F0E5CB` / `#211D16` | 清楚分层，长说明使用平整底色 |
| 危险 / 增益 | `#C76750` / `#9DB48A` | 与图标、文字标签并用，不能仅靠颜色区分 |

卡框使用可伸缩的边角/边线或等价方案，不把整张卡面拉伸到任意比例。描边、纸纹、磨损和阴影统一强度；设施扩展卡、物品紧凑卡与右栏小卡属于同一套设计。装饰不参与命中测试，不遮挡真实按钮或拖拽目标。

### 3.2 字体与信息密度

标题可用有粗糙感的中文标题字；正文和数字使用清楚、完整覆盖中文的字体，禁止让所有正文都使用难读的装饰字。字体加载失败时有可读回退，不显示方框或空白。

沿用S14要求：普通正文不小于16px，辅助信息不小于14px，操作热区不小于40×40 CSS px；对白正文不小于20px。桌面基准均以浏览器100%缩放检查，不通过整体缩放或小字换取同屏。名称过长可换行或省略后提供完整提示，关键数量、当前值/上限、耗时、危险和执行按钮不可省略到无法判断。

### 3.3 状态必须可辨

| 状态 | 视觉与行为要求 |
| --- | --- |
| 普通可用 | 主体清楚，动作可识别，非所有卡都处于强高亮 |
| 悬停 / 键盘焦点 | 轻微提亮或可见焦点线，不改变卡片尺寸、不推动邻卡 |
| 选中 | 暖金边框加选中标记，不能只用与危险相同的颜色 |
| 禁用 / 耗尽 | 降饱和并保留可读名称、原因或“已搜空”等状态；不可仅整卡变暗到看不清 |
| 拖拽有效 / 无效 | 目标边框、图标及短提示共同区分；松手行为保持原校验 |
| 危险 / 暂停 | 图标与短原因常驻可辨，“退出/继续”等关键操作不藏在花纹里 |
| 加工 / 行动中 | 真实进度和占用态；装饰动画不能制造额外时间、资源或行动提交 |

### 3.4 三种桌面尺寸

必须支持1280×720、1600×900、1920×1080。参照图的比例与这三档不同，借用视觉语言，不机械复制像素高度。

地图/场景、设施/资源、当前地面、随身物品四区要同时看到标题、可辨内容及至少一排可操作卡片；左右栏保持独立。优先收紧装饰边距、缩短插画和采用现有紧凑卡，仍不足时各区内部滚动；不能把地面/随身挤出屏幕，也不能退回整个中部纵滚来通过桌面基准验收。

锅、水与食材仍内嵌在对应设施或容器中，不退回层层详情页。图中大幅场景不应挤走点火、投木、等待烹饪或卡旁执行。低于基准尺寸及浏览器放大时沿现有滚动兜底，保证操作可达。

## 4 美术素材与覆盖清单

美术和动态UI分离：素材只承载背景、材质、场景、物件与图标；名称、按钮字、状态、数量、时间、进度与说明由程序绘制。不要从参考图裁取带有文字/数值的整块面板作为运行素材。

| 素材组 | 覆盖范围 | 交付检查 |
| --- | --- | --- |
| 背景与面板 | 一套低对比废土环境、深色面板、旧纸、边角/分隔 | 清晰缩放，接缝不明显，文案衬底稳定 |
| 场景 | 现有场景资源入口 `camp`、`field`、`woods`、`stream`、`village`、`hardware`、`scrapyard`、`clinic`；实施时以运行清单补齐新增项 | 八个入口逐项映射，无漏图；地点含义不互换。相同地点在当前/相邻卡使用同源图，裁切不截掉主体 |
| 设施与资源 | 所有已接入设施、采集/搜集点，以及需要区分的燃烧/熄灭、余量/耗尽状态 | 结构、图标与现有对象相符，不在插画中制造可拾取假物件 |
| 物品 | 当前可生成且能出现在地面/随身/锅内/预览的全部物品图标 | 同一物品各处同源；实例号、耐久、水量等动态覆盖，不能因画法不同误认成不同物品 |
| 状态与通用操作 | 属性、疾病/持续状态、携重、方向、转移、关闭、展开、导航等 | 风格统一、含义可辨；方位箭头、物品转移箭头与展开控件不会混淆 |

开发方先从运行数据和界面资源映射盘点，交付一份清单，逐条记录“对象ID / 显示名 / 出现场景 / 素材路径 / 完成状态 / 复用关系”。不能用一张概念图声明全量素材已覆盖。旧资源符合本规范可以复用；不符合的须替换。正式验收不接受正常可达对象仍用未处理的旧风格占位图或缺失图标；缺图回退只用于异常容错。

运行资源需有压缩与合适尺寸，同源图缓存复用。错误或慢加载时卡片尺寸稳定、文本与按钮可用，不显示破图遮住操作。参考原图留在本目录作为策划依据，不能作为整个游戏界面的运行背景。

## 5 开发顺序与交付物

| 步骤 | 工作 | 进入下一步的条件 |
| --- | --- | --- |
| M01 现状留样与资源盘点 | 记录实施前提交、测试环境；保存五金店和营地在三档分辨率的截图；建立素材映射及真实测试存档副本 | 基准可重现，现行交互与待确认项边界明确 |
| M02 通用主题与样板 | 完成背景、材质、字体、状态、按钮、滚动条；在五金店普通态及营地含锅状态接入 | 两个实机样板符合参考风格，三档四区可用；开发方自检后继续，无需策划二次确认 |
| M03 主界面全量应用 | 补齐全部场景、设施、物品与状态素材；接入左右栏、四区、局部浮窗、进度/暂停/结果 | 本文§2、§4覆盖清单无遗漏，主界面没有新旧风格拼接 |
| M04 实机验收与修复 | 执行验收清单，检查共用样式影响到的菜单、战斗、对白；修复并复验失败项 | 必须通过项全部通过，有截图、操作录像或日志佐证；阻断问题关闭 |
| M05 交付与上线核验 | 汇总实现提交、素材清单、验收记录、未覆盖项和截图；按现有流程发布并检查发布页 | 线上版本对应提交，资源正常加载，五金店/营地核心操作及刷新读档复验通过 |

这是一批完整的主界面换肤交付，M02是开发内部样板检查，不是可以替代M03–M05的最终成果。发布前完成全量验收，避免先将半套主题作为最终版本交付。若仓库推送会自动发布，开发方应在推送最终发布提交前做好本地验证。

开发方可自行决定纹理细节、插画裁切、组件实现、图片格式及合理性能优化。若现有布局和本案目标冲突，优先满足四区同屏、可读性和操作可达；记录视觉微调即可，不必暂停询问。若确需改变玩法、删除入口、定新角色造型或改变待确认问题的行为，才单列问题，先继续可独立完成的换肤工作。

## 6 需要策划确认的事项

本次视觉方向、主界面范围和一次性交付方式已由用户提供的参考图及本轮指令确定，**没有新增的开工前必须确认项**。色值、纹理密度、卡框细节和屏幕适配属于开发可决定的实现细节。Q14–Q22不是本次换肤的前置审批，也没有在本案中被关闭。

| 原待确认项 | 本次如何处理 |

## 7 开发完成后的回报

回报需明确区分“已实现、已验证、未验证、阻塞”，附实现提交与可试玩地址；不能用历史测试通过数替代本轮结果。至少提供两类主场景的三档截图、代表性操作录像、素材覆盖清单和逐项验收记录。开发方在S14相关位置补本轮【实现同步】及自己的修改记录，原有历史记录保留。

本次策划提交仅交付计划、验收标准和原始参考图，不表示游戏已换肤或已通过运行验收。
