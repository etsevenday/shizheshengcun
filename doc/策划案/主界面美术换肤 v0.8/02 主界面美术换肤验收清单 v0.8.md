# 主界面美术换肤验收清单 v0.8

日期：2026-10-28。配套[开发计划](<01 主界面美术换肤开发计划 v0.8.md>)。下表均为待执行验收目标，当前没有新风格实机通过结论。

## 1 测试方法与留证

1. 使用真实浏览器运行游戏，记录实现提交、浏览器版本、操作系统缩放、浏览器缩放及内容视口尺寸。三档内容视口为1280×720、1600×900、1920×1080，浏览器缩放100%；窗口外框尺寸不能冒充内容视口。
2. 基准和改后使用同一场景/状态的测试存档副本。保留原存档；可用已有测试入口或可复现操作构造边界，不篡改正式存档，不把仅有静态数据的原型当可玩版本。
3. 五金店/等价搜集场景与营地含火堆、锅、水和食材的场景，在三档各留完整截图，共至少六张。附原始截图，不用缩图隐藏小字或裁去有问题的区域。五金店原场景优先，无法进入时记录原因和可复现替代，不豁免五金店素材检查。
4. 在1280×720完成一条连续操作录像或同等可复查的逐步操作记录：选卡/取消、转移、拖拽、点火、等待烹饪/退出、移动、刷新读档。另留对白与战斗兼容回归证据。截图不能单独证明按钮可用。
5. 每项记录“通过 / 失败 / 未执行”，附证据路径、实际结果和问题编号；有失败时修复后记复验版本，不能覆盖原失败记录。若确实不适用，说明对象在当前版本不存在的依据，不能以缺少素材或未准备存档为由豁免。
6. 空闲浏览前后核对游戏时间及必要存档字段；合法行动的比较按同一初始状态和同样操作序列进行，不要求本来会耗时/消耗的行动数值保持不变。运行现有受影响的构建、检查与回归测试，结果写入验收记录；自动测试不能代替下面的实机检查。

## 3 可读性与流畅度判断

正常正文与平整衬底按至少4.5:1、明显的大字与关键非文字边界按至少3:1作为本轮设计检查目标；以最终合成效果检查，不只检查色值表。纹理可移到边缘或压暗，不能以“废土风格”解释看不清。禁用信息仍需可辨，危险和选中必须有非颜色标记。

开发方记录同一浏览器/设备/视口下改前改后的首屏加载和卡片/菜单响应，重点检查反复解码大图、滚动掉帧与点击反馈延迟。有可见持续卡顿、点击被漏掉、图像加载阻塞执行等现象即失败。此处不编造未测得的帧率或设备指标，结果必须来自本轮实际记录。

## 4 通过条件和回报模板

不能带着操作不可达、四区被挤出、真实数据错误、缺素材、新旧风格明显混用、输入锁破坏、丢档/重复扣费等问题宣称完成。纯装饰细节的轻微偏差可记录具体位置和原因，但不能用“后续优化”替代本次风格与可用性要求。

开发方先完成本地V08-A01–A21并修复失败项，再发布并执行V08-A22；本地验收完成、线上未核验时，只能写“本地通过，线上待验”。全部必须通过项及发布复验通过后，才能写“主界面换肤完成”。
