## 2 内核（src/Core）设计

### 2.1 目录与类型

```
src/Core/
├─ Config/      GameConfig 及各 *Config 类；ConfigLoader.FromJson(string)；ConfigValidator（ID 唯一、引用存在、里程碑阈值 ∈{25,50,75,100}、配方输入输出物品存在、耗时为 5 的倍数）
├─ State/       GameState, Stats, LocationState, ResourceState, ItemInstance, FacilityState, ActiveAction, SubAction, ProgressState, LogEntry, Rng
├─ Time/        Clock 静态函数：Day(minute)、TimeOfDay、IsDaylight(minute)、IsMidnightBoundary、FormatHHmm
├─ Rules/       StatRules（每小时速率、阈值伤害、自然恢复、腹泻）、WorkFactor、InventoryRules（克重、20/30 公斤、合堆、先到期先用、工具选择）、ResourceRules（预留、午夜补充公式）、FireRules、RecipeRules、WorldRules（里程碑、连接解锁、可移动校验）
├─ Actions/     ActionType 枚举；ActionRequest；ActionPreview；每类行动一个 Handler（Travel、Explore、Gather、Craft、Build、Rest、Sleep、Wait、Use、Ignite、Pickup、Drop、AddFuel、Extinguish）
├─ Engine/      GameEngine（对外唯一入口）、SegmentRunner（5 分钟段结算）、EventSink
├─ Events/      GameEvent 基类与子类
└─ Save/        SaveSerializer（Newtonsoft，schemaVersion="0.2-proto-1"）
```

### 2.2 GameEngine 对外接口

```csharp
public sealed class GameEngine {
    public GameEngine(GameConfig config);
    public GameState NewGame(uint seed);                               // 求生案 07 开局条件
    public ActionPreview Preview(GameState s, ActionRequest r);        // 只读估算，UI 案 04/06/13
    public StartResult Start(GameState s, ActionRequest r);            // 校验→生成 actionId→掷风险→预留→保存
    public SegmentResult Advance(GameState s);                         // 推进一个 5 分钟段（求生案 06）
    public void RequestCancel(GameState s);                            // 下一边界生效
    public void Resume(GameState s);                                   // 从 Paused 回到 Running
    public void CancelPaused(GameState s);                             // 暂停态下取消
    public InstantResult DoInstant(GameState s, InstantRequest r);     // Pickup/Drop/AddFuel/Extinguish：不耗时
    public StartResult StartSubAction(GameState s, ActionRequest r);   // 暂停态下的 Use/Rest/Ignite 子行动
    public IReadOnlyList<GameEvent> DrainEvents(GameState s);
    public string Save(GameState s);  public GameState Load(string json); // 版本不符抛 SaveVersionException
}
```

- 壳的驱动循环：`Start` 成功后反复 `Advance` 直到 `s.ActiveAction == null` 或 `Status == Paused`。网页壳每段之间等待约 120 ms 做进度动画，提供“跳过动画”立即跑完。
- 失败一律返回带 `Reason` 枚举和中文文案 key 的结果对象，不抛异常（校验失败、材料变化、超重等）。异常只用于程序错误。
- `Preview` 与 `Start`/`Advance` 共用同一套纯函数（耗时估算用“按当前条件逐段模拟，不改状态”的方式算出预计分钟与预计状态变化，跨昼夜按已知日程推进）。

### 2.3 GameState 字段（全部可序列化）

- `SchemaVersion`, `GameMinute`(int, 开局 480), `Seed`, `Rng`(state), `NextInstanceId`, `NextActionId`
- `Stats`: Health/Satiety/Hydration/Energy/Wakefulness/Morale 六个 double；`DiarrheaUntilMinute`(int?)，`BandageReadyAtMinute`(int)
- `AlertLatched`: 六项布尔，记录“已在阈值以下提醒过”（求生案 02 提醒与中断）
- `CurrentLocation`(string id)
- `Locations`: Dictionary<id, LocationState{Discovered, Visited, Progress, TriggeredMilestones(HashSet<int>), Facility{ShelterBuilt, BedBuilt, FireLit, FuelMinutes}}>
- `UnlockedEdges`: HashSet<edgeId>
- `Resources`: Dictionary<nodeId, ResourceState{Available(int?), Reserved, LastRefillDay, Discovered}>
- `Items`: List<ItemInstance{InstanceId, ItemId, Count, ExpiresAt(int?), Durability(int?), Owner("carried" 或 locationId), ReservedBy(actionId?)}>
- `ActiveAction`: ActiveAction{ActionId, Type, Status(Running/CancelRequested/Paused), SourceLocation, TargetId, BaseWorkMinutes, WorkDone(double), ElapsedMinutes, Reservation(物品实例 id 列表 / 资源预留数), HazardRolled(bool), HazardHit(bool), PauseReason, PlannedMinutes(固定时长类)}
- `SubAction`: 同结构，仅 Use/Rest/Ignite，存在时主行动必为 Paused；子行动本身不可被暂停（第 9A 节），不实现栈
- `Progress`: Guide 标记（field50、visitedStreamOrWoods、sleptOnce、boiled、cooked、shelterBuilt、visitedVillage、supplyReady）、SevenDayCheckShown、Dead、DeathInfo{Cause, Minute, Location}
- `Log`: List<LogEntry{Minute, Kind, TextKey, Args}>，上限 500 条
- `PendingEvents`: 内部事件队列（不序列化）

### 2.4 5 分钟段结算（SegmentRunner，严格按求生案 06）

每次 `Advance`：
0. 段前持续条件检查（不推进时间、不消耗身体）：烧水/烹饪若营地火堆未燃或段首燃料 <5 → `Paused(FireOut)` 直接返回（求生案 06 例外精度段优先于步骤表）；预留原料已腐败 → 中止，腐败原料返还当前地面，不生成产物。
1. 段首：读状态，算工作倍率 M（求生案 05：`min(2.0, 夜间×负重×低体力)`，夜间系数对 travel 恒适用，对 explore/gather/craft/build 仅当当前地点火堆未燃烧且为夜间；出处为地图案 07 的照明规则），确定本段行动类别的每小时速率，确定归零伤害（段首为 0 才计），自然恢复健康条件（仅 rest/sleep 且遮蔽且 N≥40、W≥40、M≥20）。
2. 推进 5 分钟：应用身体变化并夹紧 0–100；所有地点燃烧中的火堆燃料 −5（归 0 置 FireLit=false）；若跨 00:00：资源按 `available = min(cap − reserved, available + dailyRefill)` 补充（仅 renewable 且 LastRefillDay < 新日），物品到期标记（到期即 ExpiresAt ≤ 当前分钟）。
3. 健康 ≤0 → 死亡流程（第 2.5 节）。
4. 工作类：`WorkDone += 5 / M`；达到 BaseWorkMinutes 则完成提交（再次校验材料与条件，提交移动/探索/产物/设施；探索按 25→50→75→100 顺序处理新跨过的里程碑）。固定时长类：`ElapsedMinutes` 达到 PlannedMinutes 则完成。
5. 结算行动末尾的环境伤害（采集风险只在完成时应用，结果在 Start 时已掷定存于 HazardHit）→ 再判死 → 写日志 → 产出事件。
6. 阈值提醒：本段结束后若某状态首次向下越过阈值且 `AlertLatched` 未置位，则置位并把主行动置为 `Paused(StatAlert)`；恢复到阈值以上后清除 latch。比较方式严格按求生案 02：饱食/水分/清醒度 **≤20**，体力/精神 **<20**，健康 **≤25**（JSON 里 lowEnergyExclusive / lowMoraleExclusive 的命名即此意）。状态归零时的处理见第 9 节。
7. 取消：`Status == CancelRequested` 的行动在本段结束后处理：探索/移动不提交结果（位置保持起点），搜集/加工释放预留（物品 ReservedBy 清空，资源 Reserved 归还），设施不生成。已耗时间不返还。
8. 每段结束后重算预计完成时刻（逐段模拟，不改状态），供 ActionBar 显示。

**预留语义**（搜集案 05 算例是唯一正确解释）：Start 时 `available −= n, reserved += n`；完成时只 `reserved −= n`，不再扣 available；取消时 `reserved −= n, available += n`。物品预留同理：预留时先把所需数量从堆里**拆成独立实例**再置 `ReservedBy`，完成时删除该实例，取消时清 `ReservedBy` 并允许重新合堆。`ReservedBy != null` 的实例拒绝一切拾取/放下/食用/投料；主行动存续期间（含暂停）其预留实例与催化工具实例（锅、打火器、正在用的斧/刀）禁止 Drop。

精度例外（求生案 06）：火堆燃料段首 ≥5 则本段有效；食材恰在完成时刻到期视为腐败。工作最后一段不足也按完整 5 分钟结算，不保留余数。

### 2.5 死亡与结束

健康归 0：终止行动（移动中位置记为起点），返还预留物到死亡地点地面，`Dead=true`，记录原因（最后一次导致健康下降的来源：饥饿/缺水/缺睡/过劳/采集受伤）、存活分钟、已探索地点数、七日检查四项进度。死亡后 `Start`/`Advance` 全部拒绝。

### 2.6 随机数

实现 `Rng`：xorshift32，字段 `State(uint)`，方法 `NextDouble()`；状态进存档。每个带风险的搜集在 `Start` 时掷一次并把结果存进 `ActiveAction.HazardHit`，读档不重掷。NewGame 的 seed 由壳传入（网页壳用 `DateTime.Now.Ticks` 低 32 位，死亡结算显示 seed）。

### 2.7 关键规则速查（易错点，实现与测试都要对照）

- 时间：第 1 日 00:00 = 分钟 0，开局 480；昼 06:00–18:00；所有耗时为 5 的倍数。
- 地点状态迁移：连接解锁 ⇒ 另一端 `Discovered=true`；移动完成 ⇒ 目标 `Visited=true`，并把该地点 `revealOnVisit` 的资源点置 `Discovered`；里程碑结算 ⇒ `revealAt ≤ 新进度` 的资源点置 `Discovered`。NewGame：营地 Visited/Discovered/Progress=100，农野荒地 Discovered，其余未知；资源 `Available = cap`（水源 null），遗迹容器 1。
- 移动：只能去已解锁连接的相邻地点；位置在完成时一次更新；移动过程（含暂停）不能访问任何一端的地面，Pickup/Drop 一律拒绝，子行动 Use 只能用随身物品；移动暂停期间的休息一律按露天结算；午夜不打断移动。
- 探索：基础 30 分钟 +25 探索度；营地与探索度 100 禁用；只发现不产物；取消不加探索度；里程碑按“地点ID+阈值”只触发一次；无内容阈值照常推进。
- 资源：自然资源按产物件数扣库存（工具加产多扣）；不足时采尽余量、耗时不减；一次性容器扣 1 次给整组；水源无限；石块与遗迹不补充；预留跨午夜按公式计算，取消后释放。
- 工具：自动选随身耐久最高者，平手按实例 ID 小者；成功完成扣 1；失败/取消不扣；耐久 0 无效且不消失；石刀使纤维耗时 20→10（field_fiber 与 woods_fiber 两处都配），斧使木材产出 1→2；打火器必须随身才能点火。
- 负重：克重整数求和；≤20000 轻装；>20000 系数 1.25；>30000 禁止拾取（恰好 30000 允许）；地面无上限。
- 合堆：同物品且同 ExpiresAt 才合堆；堆满分新堆；工具各占一实例；消耗顺序：到期时间升序 → 同批次随身优先于地面 → 实例 ID 升序。
- 保质：生成时记 ExpiresAt；到期标腐败，不能吃不能做配方，保留重量可丢弃；加工中原料不冻结保质期；熟食从出锅时刻重算。
- 火堆：开局未点燃；点火需随身打火器且燃料 ≥5（不足则先投料，燃料 0 时至少 1 木材），耗 5 分钟（按 craft 速率消耗身体），点火段本身消耗 5 分钟燃料；投木材不耗时，+60，`fuel+60>240` 时拒绝且不扣木材；燃烧按全局时间；主动熄火不耗时、燃料保留。
- 配方：7 条，全开局已知；材料来自随身与当前地面；催化工具须随身且不消耗；烧水/烹饪仅营地燃烧火堆；遮蔽棚与床垫各一次，床垫需棚；建造在营地。
- 即时使用：饮水/进食/绷带为 5 分钟即时动作，确认时先扣物并应用效果，再推进 1 段 wait 消耗；绷带角色级 60 分钟冷却，冷却中不扣物；脏水必定腹泻 12 小时（刷新不叠加）；生块根与腐败品不可食（不扣物不耗时）。
- 休息：30/60/120，每小时 +20 体力，不恢复清醒；营地有棚时 +2 精神/小时。睡眠：2/4/8 小时；遮蔽（五金店、诊所、有棚营地）12 清醒 15 体力 1 精神；露天 6 清醒 10 体力 −0.5 精神；床垫额外 +5 体力/小时。精神 <20 时休息与睡眠的体力正向恢复都 ×0.5。不因满值自动结束。
- 点火按 craft 速率消耗身体，但不算“工作动作”（体力 0 时不触发 −1 健康/小时）；建造按 craft 速率并算工作动作；即时使用按 wait。
- 暂停态允许的即时操作白名单：投料、熄火、查看；拾取/放下/整理物品不允许（移动暂停时更不允许）。子行动只允许 Use（饮/食/绷带）、Rest、Ignite。
- 阈值伤害：N=0 → H −2/h；W=0 → −8/h；S=0 → −2/h；E=0 且工作中 → −1/h；可叠加；腹泻额外 W −3/h。
- 引导与七日检查：求生案 07 表；第 8 日 08:00（分钟 10560）存活时触发一次，显示四项进度，可继续。
- 存档：每次动作开始、每段、完成、取消后保存；单槽；带 schemaVersion；读档续行不重扣材料、不重掷、不重发里程碑、不跳时。

### 4.2 交互规则（UI 案 10 状态机必须完整实现）

浏览中不推进时间；同时只一个主选中对象；右侧唯一主按钮；执行中禁止第二主行动；取消请求在边界生效；暂停态只允许继续/取消/允许的子行动；子行动中保留主行动条；完成后结果条；死亡锁定。Esc 只关浏览层，不取消主行动。数量框打开时背后点击无效。双击主按钮不重复提交（按钮在 Start 返回前禁用，并靠 actionId 去重）。快捷键：M 地图、C 加工、R 休息、L 日志、Esc 关闭当前浏览层。ActionBar 每段显示重算后的预计完成时刻，文案用“预计”。引导目标：三天引导全部显示在左栏，已达成项打勾，当前日高亮。

### 4.3 文案

全部中文，遵守 UI 案 11 的句式：主要操作“动词+对象(+时间)”，禁用原因说明缺什么，风险“概率+具体损失”，完成“物资加减+实际位置”，时间区分“预计/实际”。颜色不单独承载信息，同时给文字或符号。

## 9 已确认与已做假设（执行者不必再问；M0 时整体抄入 `doc/开发计划 v0.1.md` 第 6 节并注明 2026-10-22）

### 9A 策划已拍板（2026-10-22）

- 燃料上限：`fuel + 60 > 240` 时拒绝投料，不扣木材，提示“燃料不足 60 分钟空位”。
- 归零暂停：状态在阈值提醒后继续降到 0 时，再暂停主行动一次（`Paused(StatZero)`），说明正在扣健康；同一区间不重复；回到 >0 再归零时重新触发。归零与死亡优先级高于普通提醒。
- 子行动不可再暂停：子行动（Use/Rest/Ignite）期间越过的阈值只记录 latch，子行动结束回到暂停层时一并展示；死亡照常处理。`GameState.SubAction` 保持单个，不实现栈。
- 点火余量：燃料 <5 时拒绝点火，提示“请先投入木材”；燃料为 0 且无木材同样拒绝。

### 9B 本方案假设

1. 等待动作：30 / 60 分钟，任何地点可用，按 wait 速率，固定时长，可在边界取消。
2. 探索/采集/加工在“有燃烧火堆的地点”夜间不吃 1.5 倍（出处地图案 07 照明规则；求生案 05 措辞略窄，以地图案为准），实际只有营地有火堆。
3. 动画节奏：每 5 分钟段 120 ms，可一键跳过；睡眠 8 小时 96 段约 12 秒，跳过后立即结束。
4. 行动日志条目：时间、类型、文案；最多保留 500 条。
5. 存档：浏览器 localStorage 单槽，key `survival.save.v1`；清除存档在设置里，二次确认。
7. 种子：新游戏随机，死亡结算与七日检查界面显示，便于复现反馈。
8. 开局营地 `Visited=true, Discovered=true, Progress=100`；农野荒地 `Discovered=true`；其余全未知。
9. 探索完成时若同时跨过多个阈值（不可能，每次只 +25），仍按顺序循环处理以防配置修改。
10. 熟食与草药的 ExpiresAt 用“生成分钟 + shelfLifeMinutes”；开局营地地面物品无保质期项，不设 ExpiresAt。
11. 网页最小宽度 1280，小于时允许横向滚动，不做手机布局（已确认 PC 优先）。
12. 不做音频、不做云存档、不做 PWA。
13. 引导标记“携带或营地有净水3与熟块根2”为达成即锁存，之后消耗不回退；其余引导标记同样锁存。
14. 七日检查为非阻断事件：第 8 日 08:00 所在段结束后触发，不暂停主行动，主行动结束后弹出结算层；若当时空闲则立即弹出。
15. 死亡原因取最后一次使健康下降的来源，同段多来源按 饥饿 > 缺水 > 缺睡 > 过劳 > 受伤 取第一个。
16. 移动暂停期间休息按露天结算（起点是否遮蔽不影响）。
17. 点火不算工作动作；建造算工作动作。
18. 打火器与金属锅必须随身。
