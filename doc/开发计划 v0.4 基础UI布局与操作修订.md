## 3 开发假设（规则解释，不含数值）

1. 第一行与第二行是两个独立的横滚容器；当前地图卡不放进横滚容器、直接固定在第一行最左，相邻地图子栏单独横滚。中部 `.center-scroll` 纵滚，左右栏不随中部滚动。二级面板（地图、制作、休息、日志）打开时中部锁定不滚，面板盖住地块两行与地面，随身栏留在下方。
2. 地块区整块的半透明场景底图与暗层移除；场景图只作当前地图卡的大图，地名/室内外/昼夜放左上与右上衬底，探索度与按钮放底部渐变衬底。
3. 第二行顺序：火堆 → 遮蔽棚 → 床垫 → 分组标题“采集资源” → 已发现资源卡；两组之间用竖线间隔与标题（“设施”“采集资源”）区分，未建棚/床仍按 v0.4 显示虚线框。没有设施的地点只有“采集资源”组。
4. 选中模型扩展：`SelectionKind.Facility`（Id = 设施 ID）与 `PotLiquid`（InstanceId = 锅实例，Id = 液体物品 ID，Owner = pot:&lt;锅ID&gt;）；锅、锅内食材、直烤食材沿用 Tool 按实例 ID 选中。展示路径用内核 WherePath 现算，右栏与卡下操作条读同一个 `G.Selected`；选中随状态校正：烤熟改物品 ID 仍选同一实例、取出跟到新位置、脏水净化后跟到新液体、喝完或倒空清空。
5. 锅卡只有一个组件 `PotCard`，地面栏、随身栏、火堆加工位三处共用：锅图与“金属锅#N”、水量条（含毫升与烧水受热）、每种液体一行（图标、×份数、毫升、“已预留N毫升”，全部被预留时行下写 ReservedWaterText）、最多两个食材行（图标、名称#实例、加工状态与受热条）、空食材位提示。锅在火堆内时只在火堆卡内渲染。
6. 火堆卡：头部（火堆图、燃烧状态、燃料 n/上限与进度条，即燃料区热区）→ 两个加工位（锅位 PotCard、直烤位 FoodCard、空位保留 fireslot: 热区）→ 底部“投入木材”“点燃/熄灭”。点火堆主图或卡面空白只选中火堆；锅、水、食材、空位各自阻止冒泡。
7. 操作条是被选中卡片正下方的普通文档流：地面/随身卡外包 `.card-col`，条在卡下（宽 300px，推开后面的卡片，不遮挡）；锅内子对象的条在该行正下方、仍在锅卡/火堆卡内，卡片高度随之变化，第二行与地面/随身栏按内容高度排（中部纵滚）。一次只有一条。
8. 地面/随身卡的卡角三角箭头（点一下转 1 件、长按连续）保持不变；地面/随身栏里的锅卡标题行也保留这个箭头。v0.7 第 3.2 节“三角箭头打开转移操作条”只用于锅内液体/食材行、火堆里的整锅与直烤位（▾ 按钮：选中该对象并打开操作条）。
9. 自用按钮文案来自内核 `UseButtonText`：“食用1份”“饮用1份”“饮用1份（风险）”（配置 causesDiarrhea）、“使用1份”（绷带）；按钮旁写效果、5分钟（含自然消耗）、属性变化、溢出与腹泻后果。可自用（配置 use 不为空）但暂不可用时禁用并写内核原因；材料、工具、空锅、生块根不出现自用按钮。右栏 ItemDetail 只保留详情、预测与说明；暂停层 PauseLayer 的补给按钮是既有特殊路径，保留。
10. 删除 `DropTargetKind.Self`；拖到左栏、右栏（含人物页签）或任何非落点处都是无效落点，原物归位，拖动标签与松手提示“选中物品后在卡片下方使用”。
11. 点火拖拽：`DropVerb.Ignite` 非预览，`DropIntent.Action = ActionRequest.Ignite(工具实例)`；壳层松手即开始，requestId 用起拖时生成的那一个；悬停在合法火堆落点时 drag.js 调 `DragHover`，右栏临时显示“用打火器#N点火”的预测，离开或松手清空。
12. 点火菜单 `IgniteMenu` 是火堆卡“点燃”按钮下方的小弹层（不是 Panel、不带遮罩、不禁拖）；列表来自 `IgniteToolOptions`（随身与当前地面每把打火器：图标、名称#实例、来源、可用/原因）；点一把可用的即开始（新 requestId + 组件级防连点），菜单关闭；无可用工具写“没有可用点火工具”及原因；Esc 或点菜单外只关闭。Esc 栈：拖拽中 → 数量框 → 点火菜单 → 二级面板 → 清选中 → 菜单。
13. 点火子行动、主行动暂停、自动投木等全部沿用内核现有校验与提交；预测新增结构化字段（点火前/开始后/完成时燃料、是否自动投木、是否完成即熄灭）供菜单提示与右栏使用。
14. 右栏：顶部固定行动区（执行/暂停中的行动进度与继续/取消）→ 固定页签“对象信息 / 人物” → 详情区；悬停预测临时覆盖详情区，离开恢复；无选中（开局、Esc 清选中）默认人物页，选中任何对象或打开二级面板自动切到对象信息；点“对象信息”而对象已消失显示“未选中对象”。页签只在会话内。
15. 人物页：日期/时刻/昼夜/遮蔽、六项属性（数值、阈值、状态、`Ui.StatExplain` 说明）、负重与超重规则、状态异常（`ActiveConditions`）；左栏 Hud 与属性说明弹层读同一查询。不显示免疫力、熟练度、AP。
16. 滚轮：`wheel.js` 在 document 捕获 wheel，从目标向上找第一个“在该方向还能动”的容器手动滚动并阻止默认，一次输入只由一个容器消费；纯竖向滚轮遇到只横向溢出的栏（data-wheel="x"）改为横滚；Shift+滚轮横向；触控板原生横向按原生方向；Ctrl+滚轮放行；数量框是文本框，滚轮不改值；横向栏到边界交给中部纵滚，纵向列表到底只交更外层纵向容器、不改成外层横滑。拖拽中同样生效，drag.js 用最后指针坐标重算。
17. 存档不升级；点火菜单与页签在回标题、换地点、开二级面板时收起或复位。
18. 1280×720（屏高 ≤800px）第一行 180px、第二行普通卡 182px（行高约 220px），超出靠中部纵滚；所有矮屏覆盖段合并为文件末尾一处。
19. SurvivalBot、PlaythroughTests 走内核请求不经 UI，不受影响；FeedbackBridge 的“当前画面”写点火工具菜单与右栏页签。
20. 通过“饮用1份”直接喝正在净化的锅中脏水不清零净化进度（现状），记入待确认，不改。

## 4 实施记录与偏差

1. 计划把“拖拽松手即点火”的壳层分派放在 M30；但 M26 删掉 PreviewIgnite 后旧分派会走即时分支出错，所以 M26 已在 ExecuteDrop 里接上 StartsAction（松手即 BeginAction），M30 再补悬停预测。M26 提交后发现 Web 工程有一处变量重名编译错误（`dotnet test` 只编译测试工程，没暴露），在 M27 之前用 amend 修进了 M26，提交号为 e53b652；之后每个里程碑提交前都同时跑 `dotnet build web/Survival.sln`。
2. 当前地图卡没有用 sticky，而是直接放在第一行横滚容器之外，效果相同（相邻地图横滚时位置不变），实现更简单。
3. 点火菜单在火堆卡内、按钮正下方的文档流里展开（带指向按钮的小箭头），而不是绝对定位的浮层：第二行是横滚容器，绝对定位的弹层会被裁掉。它仍不是二级面板、不盖地块栏、不禁拖，但会撑高火堆卡。
4. 地面/随身栏从固定高度改为最小高度（1280×720 186px），锅卡（三四行内容）与卡下操作条会把栏撑高，由中部纵滚到达。
5. 右栏的行动进度原来独占整栏，现在固定在页签之上，下面仍可浏览对象/人物；暂停时仍由中部暂停层操作继续/补给/取消。
6. 内核溢出提示比原 ItemDetail 多算了“精神溢出”（同样是 0–100 夹紧的既有规则，只是多显示一项）。
7. 选中卡下操作条里，单件物品的转移按钮写实例名（“拾取金属锅#1到随身”），堆叠物品写份数（“拾取2份到随身”）；锅内液体与设施里的物品有“随身 / 当前地面”目标选择，默认目标为对面（在随身的锅默认取到地面）。
8. 浏览器手测里 `dotnet run` 的静态文件带 `?v=dev`，浏览器会缓存旧脚本；发布流水线会把 `?v=dev` 换成提交号，本地手测时需强制刷新。
9. 手测修正（M33）：左栏腹泻/绷带冷却行与属性说明弹层原写作 `还剩@Clock.Duration(...)`，Razor 把紧跟汉字的 @ 当作普通文本，界面直接显示了“@Clock.Duration(…)”字样（旧版腹泻行同样有此问题），改为 `@(…)`。
10. 手测修正（M33）：读档升级说明原来只在“未选中对象”详情里显示，默认人物页看不到；人物页顶部也显示同一条提示。
11. 手测修正（M33）：火堆卡锅位加宽到 300px，锅内对象的操作条不再挤成窄列。
12. 手测修正（M33）：人物页标题改为“人物信息”。
13. 1280×720 下当前地图卡宽约占第一行的 58%（410×158），1600×900 下约 59%（592×202）；底部按钮衬底占卡高约 35%，其上部约四成是透明渐变，左上/右上衬底不跨全宽，场景图约七成以上清楚可见。
