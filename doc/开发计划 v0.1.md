# 适者生存 开发计划 v0.1

2026年10月22日 ｜ 依据：基础系统 v0.2 三份系统案、UI 策划案 v0.1、基础系统初始配置 v0.2.json

## 0 目标与原则

- 产出一个能在浏览器里直接玩的“七日基础生存检查”原型，发一个链接给朋友即可试玩。
- 内核为纯 C#，不引用任何 UnityEngine API；网页壳用 Blazor WebAssembly 先做，UGUI 壳之后接同一份内核源码。
- 策划案里的验收用例（地图 M01–M09、搜集 G01–G08、求生 S01–S12、界面 U01–U20）就是完成标准，全部写成自动化测试或手动验收项。
- 策划案写明“配置值可调但不能由开发各自补定”。开发中遇到规则空白一律记入本文件第 6 节，由策划拍板后再实现，不自行补数。

## 1 工程骨架

```
shizheshengcun/
├─ doc/                                  策划案与本计划
├─ data/
│   └─ config.v0.3.json                  结构化配置（由 v0.2 转换，里程碑与解锁条件改为结构化字段）
├─ src/
│   └─ Core/                             纯 C# 内核源码（唯一来源），只放 .cs
│       ├─ Survival.Core.asmdef          noEngineReferences = true
│       └─ package.json                  将来 Unity 工程用本地包方式引入（manifest 里 file:../../src/Core）
├─ web/                                  .NET 8 解决方案
│   ├─ Survival.sln
│   ├─ Survival.Core/                    netstandard2.1 类库，csproj 链接 ../../src/Core/**/*.cs
│   ├─ Survival.Core.Tests/              NUnit，承载 M/G/S 三组验收算例
│   └─ Survival.Web/                     Blazor WebAssembly 壳，wwwroot/config 链接 data/
└─ .github/workflows/pages.yml           推送 main 自动发布到 GitHub Pages
```

本轮不建 Unity 工程（2026-10-22 决定）。src/Core 目录按 Unity 本地包的格式组织，asmdef 与 package.json 先就位，之后建 UGUI 壳时在 Unity 的 manifest.json 里加一行本地包引用即可，内核源码不需要搬动或复制。

约束：

| 项目 | 约定 | 目的 |
| --- | --- | --- |
| 内核语言级别 | C# 9，目标 netstandard2.1 | Unity 2022.3 与 .NET 8 两边都能编译 |
| 内核依赖 | 仅 BCL 与 Newtonsoft.Json | Unity 有官方 Newtonsoft 包，不用 System.Text.Json |
| 随机数 | System.Random，种子与状态进存档 | 满足“读档不重掷”的要求 |
| 时间 | 内核不读系统时间，只接受“推进 5 分钟”指令 | 浏览不推进时间，离线不推进 |
| 引擎隔离 | asmdef 关引擎引用 + .NET 侧独立编译 | 两边编译器共同保证内核不依赖 Unity |
| 测试框架 | NUnit | 与 Unity Test Runner 同框架，后期可在 Unity 内复跑 |

## 4 开发里程碑

每个里程碑结束时网页可运行、测试全绿、并推送到 Pages。顺序遵循三份系统案各自给出的实施顺序。

### M0 骨架

- git 仓库、src/Core 目录（含 asmdef 与 package.json）、.NET 解决方案与三个工程、Pages 工作流。
- 配置 JSON 从 v0.2 转换为结构化 v0.3，内核能加载并校验（ID 不重复、引用存在）。
- 网页打开显示一张空白桌面与版本号。
- 验收：两边编译通过；Pages 上能打开页面。

### M1 时钟与身体状态

- Clock、Stats、WorkFactor；等待动作作为第一个可执行行动。
- 网页：HUD 六项状态、日时、昼夜、“等待 30 / 60 分钟”行动按钮（正式行动，非调试用）。
- 验收：S01、S02、S03、S06、S08。

### M2 地图、移动与探索

- World、Actions 基础事务（开始、逐段推进、边界取消）、Preview 的移动与探索部分。
- 网页：地点卡、入口卡、地图总览、行动详情、行动进度条。
- 验收：M01–M06、M08、U01–U04、U15、U16。

### M3 资源、背包与搬运

- Resources、Inventory、Tools；采集与遗迹搜集；风险掷定；午夜补充。
- 网页：资源点卡、地面区、随身区、数量框、采集预览与结果条。
- 验收：G01–G05、G07、M07、U05–U08。

### M4 火堆、加工与设施

- Fire、Recipes、保质与腐败、遮蔽棚与床垫。
- 网页：加工面板、火堆状态、熄火暂停与投料点火子行动。
- 验收：G06、G08、S10、U10、U11。

### M5 休息、睡眠、阈值暂停与死亡

- 休息与睡眠行动、自然恢复健康、Alerts、补给子行动、死亡终止。
- 网页：休息睡眠面板、危险暂停层、即时使用入口。
- 验收：S04、S05、S09、S11、U09、U12–U14。

### M6 存档

- Save 全量序列化、activeAction 续行、版本拒绝；网页用 localStorage 单槽。
- 网页：保存状态提示、保存失败提示、继续按钮。
- 验收：S12、M09、U20。

### M7 开局、引导、七日检查与日志

- Progress、Log；开始界面、死亡结算、七日检查提示；前三日引导标记。
- 验收：U17、U18、U19，以及按求生案 07 录制一条保底路线并留档。

### M8 发布与分享

- 中文字体子集化、1280×720 与手机横屏检查、加载提示、版本号与反馈入口。
- 朋友试玩后按求生案 07 记录死亡来源、往返时间、补给次数等数据。

### 后续（不在本轮）

- UGUI 壳：Unity 工程 Game 目录，引用同一 Core。
- 策划案挂起的系统：侵蚀、轮回、超能力、善恶值、招募、联机、战斗、天气、生态。

## 5 发布方式

- GitHub Pages 托管 Blazor 静态产物，推送 main 自动构建。
- 存档存在浏览器 localStorage，换浏览器不共享；首版不做云存档。
- 页面带版本号与构建日期，朋友反馈时可对应。

### 2026-10-22 规则补充（策划拍板，详见 doc/实施方案 v0.1.md 第 9 节）

| 事项 | 决定 |
| --- | --- |
| 火堆燃料上限边界 | 投料后超过 240 分钟时拒绝投料，不扣木材 |
| 状态归零时 | 在 20/25 阈值暂停之外，归零时再暂停主行动一次 |
| 子行动期间再越阈值 | 子行动不可再被暂停，只记录，结束后回到暂停层一并展示；不实现子行动栈 |
| 点火余燃料不足 5 分钟 | 拒绝点火，要求先投料 |
| 等待动作 | 30 / 60 分钟，任何地点可用 |

其余开发假设（引导锁存、七日检查非阻断、死亡原因取法、点火不算工作动作等）见实施方案第 9B 节。
